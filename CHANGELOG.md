# Changelog

## V1.2.29

### Wi-Fi: драйвер Intel AX201 (iwx) — этап 2, сканирование эфира
После этапа 1 драйвер перезапускает прошивку в рабочем режиме, настраивает её и делает пассивное сканирование всех разрешённых каналов 2,4 и 5 ГГц. Найденные сети выводятся в лог. Подключения пока нет. На железе ещё не проверено.

**Рабочий запуск прошивки** (порядок как в `iwx_init_hw` из OpenBSD)
- После чтения NVM устройство останавливается и запускается заново, прошивка грузится второй раз, уже без `NVM_GET_INFO`. DMA-буферы секций прошивки и IML при повторной загрузке переиспользуются, а не выделяются заново.
- Команды настройки: `TX_ANT_CONFIGURATION`, `BT_CONFIG`, `SOC_CONFIGURATION` (встроенная карта, задержка LTR 2500 мкс, low-latency xtal, 12000 мкс: значения для 51f0, как в Linux `iwl_so_long_latency_trans_cfg`), `DQA_ENABLE`, `LTR_CONFIG`, `TEMP_REPORTING_THRESHOLDS`, `POWER_TABLE` (энергосбережение выключено), `MCC_UPDATE`, `SCAN_CFG`, `BEACON_FILTERING` (фильтр выключен). Необязательные команды отправляются по флагам возможностей из TLV.
- `MCC_UPDATE` с кодом «ZZ» запрашивает у прошивки текущий регион. По ответу (формат v3 или v4, по флагу `MCC_UPDATE_11AX_SUPPORT`) строится список разрешённых каналов, отмечаются каналы только для пассивного скана. Если LAR выключен, используется список каналов из NVM.

**Сканирование**
- Запрос `SCAN_REQ_UMAC` версии 17 или 14, по таблице версий команд из прошивки (каналы в формате v5 или v1/v2). Сканирование пассивное (`FORCE_PASSIVE`), адаптивное время на канале, одна итерация, приоритет `EXT_6`. Шаблон probe request (заголовок, наборы скоростей 2,4/5 ГГц) уже собирается под будущий активный скан.
- Команды длиннее 320 байт (запрос скана около 2 КБ) отправляются через отдельный DMA-буфер на 4 КБ, как в OpenBSD.
- Ответ на команду теперь возвращается вызывающему для любой команды, а не только для `NVM_GET_INFO`. Коды группы `LONG` в приёмнике приводятся к обычным.
- Разбор `REPLY_RX_MPDU` (дескриптор v3 на 64 байта, семейство AX210): проверка CRC и overrun, учёт выравнивающих 2 байт. Из beacon и probe response берутся SSID, канал (DS Parameter Set), уровень сигнала (лучший из двух антенн), шифрование (RSN, WPA vendor IE, бит Privacy). Сети собираются в таблицу по BSSID, до 64 штук.
- Конец скана определяется по `SCAN_ITERATION_COMPLETE_UMAC` и `SCAN_COMPLETE_UMAC`, таймаут 15 с. В логе выводится время, число кадров и список сетей; в BSSID видны только префикс производителя и последний байт.
- Буфер приёма после обработки снова публикуется в кольце; MPDU не печатаются в лог по одному.

### Тише лог аудио
Отладочная трассировка HDA-драйвера (каждый verb, CORB/RIRB, MMIO-запись, опрос громкости) больше не попадает в лог: это примерно 1400 из 2400 строк загрузки на ноутбуке. Вызовы остались в коде за макросами `audio_dbg`/`audio_dbgf` и включаются сборкой с `-DAUDIO_VERBOSE=1`. Сводка инициализации (контроллер, кодек, выходы, выбранный маршрут) и ошибки печатаются как раньше.

### Wi-Fi: драйвер Intel AX201 (iwx) — этап 1, прошивка запущена на железе
Первый шаг к Wi-Fi на ноутбуке ASUS (Intel Wi-Fi 6 AX201 160 МГц, CNVi в чипсете Alder Lake-P, PCI `8086:51f0`). Карта находится, прошивка Intel загружается, отвечает «alive», принимает команды и отдаёт свои параметры. Сканирования, подключения к сети и передачи данных пока нет.

**Почему OpenBSD iwx, а не Linux iwlwifi**
- iwlwifi (mvm) — около 80 тыс. строк, целиком построен на mac80211/cfg80211; перенос потянул бы за собой беспроводной стек Linux.
- iwx(4) из OpenBSD поддерживает AX200/AX201/AX210/AX211, это один файл на ~13 тыс. строк, лицензия ISC, зависимости только от net80211. Прошивка и протокол команд те же, что у Linux.

**Сторонний код и прошивка** (`third_party/openbsd-iwx/`)
- `if_iwx.c` (ревизия 1.230), `if_iwxreg.h`, `if_iwxvar.h` без изменений, с копирайтами OpenBSD.
- `firmware/iwx-so-a0-hr-b0-77` — это `iwlwifi-so-a0-hr-b0-77.ucode` из пакета linux-firmware-intel (iwx рассчитан на API 77; Linux на этой карте грузит 89). Рядом лицензия Intel на прошивку (распространение в неизменном виде).
- Прошивка добавлена в `assets/manifest.txt`: попадает в ISO модулем Limine и на диск в `/lib/firmware/`.

**Драйвер** (`src/drivers/net/iwx/`)
- `iwx_compat.h` подключает `if_iwxreg.h` как есть (типы BSD, `__packed`, `htole*`, минимальные `ieee80211_frame` и константы), регистры и форматы команд не перепечатывались вручную.
- `iwx.c` — перенос логики iwx для этой карты (MAC SO, RF HR2, семейство AX210, путь gen3):
  - подготовка и сброс устройства, питание и такты (prepare_card_hw, sw_reset, apm_init), доступ к периферийным регистрам через NIC lock;
  - разбор TLV-файла прошивки: 52 секции (LMAC 15, UMAC 15, paging 20), загрузчик IML, версии команд, возможности;
  - DMA-структуры: context info gen3, prph scratch, кольцо приёма на 512 буферов, командная очередь на 256 TFD с таблицей длин;
  - запуск прошивки через `CPU_INIT_RUN`, ожидание ALIVE (аппаратная причина и пакет), шаг PNVM, команды `INIT_EXTENDED_CFG` и `NVM_ACCESS_COMPLETE`, ожидание `INIT_COMPLETE`, чтение MAC из OTP и `NVM_GET_INFO`;
  - работа опросом, без прерываний; при падении прошивки выводятся её таблицы ошибок LMAC/UMAC.
- Запускается отдельным потоком ядра `iwx`; на машинах без этой карты (VirtualBox) сразу выходит.
- В логе MAC-адрес маскируется: печатается только префикс производителя.

**Результат на ноутбуке** (первая же загрузка)
- Прошивка 77.f92b5fed.0 ответила «alive» через 141 мс (статус `0xcafe`, формат v6). Флаг ALIVE выставляется в `CSR_INT` и при замаскированных прерываниях, запасной путь не понадобился.
- Команды подтверждены за 4–8 мс, `INIT_COMPLETE` через 65 мс, MAC-адрес из OTP совпал с тем, что видит Linux.
- По NVM: 2,4 и 5 ГГц, 802.11n/ac/ax, антенны 2x2, региональные настройки (LAR) включены.

**Дальше**: сканирование эфира, ассоциация с открытой сетью, WPA2 (4-way handshake из OpenBSD net80211, примитивы SHA-1/HMAC/AES в libxcrypt), передача данных и подключение к имеющемуся стеку (ARP, DHCP, DNS, IPv4, TCP/UDP).

### Железо ASUS (по логу с ноутбука): BAR для I2C-контроллера тачпада, биты статуса EC
- Тачпад теперь находится по `_CID` (`candidate ETPD hid=ASUE1411 cid=PNP0C50 addr=0x15 irq=40`), тайминги SSCN/FMCN читаются. Но прошивка ASUS оставляет BAR0 у LPSS I2C 00:15.0/00:15.1 пустым (Linux назначает его сам: `BAR 0 [mem 0x4017001000] assigned`), а драйвер такие контроллеры молча пропускал. Теперь, если BAR0 пустой, драйвер берёт 64-битное окно памяти корневого моста PCI из ACPI `_CRS` (`acpi_pci_root_mem64_window`, PNP0A08/PNP0A03), выделяет страницу у верхней границы окна (проверяя, что там нет BAR других устройств), записывает BAR и включает декодирование. Каждый пропущенный контроллер пишется в лог с сырым BAR0.
- Слот 0x1f (LPC, SMBus, SPI) исключён из кандидатов: в прошлый раз драйвер сбросил LPSS и записал REMAP на SPI-контроллере флеш-памяти 00:1f.5.
- EC: биты статуса были перепутаны (по спецификации ACPI бит 0 это OBF, бит 1 это IBF). В VirtualBox EC нет, поэтому ошибка не проявлялась; на ноутбуке статус `0x21` и батарея молча считалась отсутствующей. Значение `_STA` батареи и ошибка его вычисления теперь пишутся в лог.
- Тачпад на ноутбуке ASUS заработал (второй лог): контроллер 00:15.1 переведён из D3 в D0, BAR назначен на `0x7ffff00000`, HID-дескриптор ELAN 04f3:3289 прочитан, сброс подтверждён, режим тачпада включён, работает по прерываниям (IO-APIC пин 40, вектор 0x61), около 6700 отчётов без потерь.
- Батарея и EC: в DSDT ASUS лежат заглушки из эталонного кода Intel, `\_SB.PC00.LPCB.H_EC` (PNP0C09) и `H_EC.BAT0`/`BAT1` (PNP0C0A), у всех `_STA` возвращает `Zero`. Настоящие устройства: `\_SB.PC00.LPCB.EC0` и `EC0.BAT0`. Раньше брались первые найденные, то есть заглушки: обработчик EC вставал на H_EC, и регион EC0 оставался без обработчика. Теперь EC берётся по пути из ECDT (поле EC_ID), а при его отсутствии пропускаются устройства с `_STA` без бита present; батарея выбирается среди PNP0C0A с битом present, предпочтительно с битом «батарея вставлена». Все кандидаты пишутся в лог.
- Зависание при загрузке на ноутбуке (третий заход): после установки обработчика на настоящий EC0 события EC (`SCI_EVT`, статус 0x20) разбирались прямо в `acpi_init`, до запуска планировщика. Один из методов `_Qxx` прошивки ASUS не вернулся (последняя строка на экране: `ignoring firmware Notify(EC0.AC0, 0x80)`), и ядро висело больше часа. Теперь при загрузке события не трогаются; их разбирает отдельный поток ядра `acpi-ec` (раз в 250 мс, только после запуска планировщика), перед и после каждого `_Qxx` пишется строка в лог с временем выполнения. Если метод зависнет, застрянет только этот поток. Опрос батареи событий больше не разбирает.
- Найдено, не исправлено: раздел ext2, созданный установщиком на 1 КБ блоках, Linux не монтирует (`Block bitmap for group 1 not in group (block 8192)`, «feature flags set on rev 0 fs»).

### Тетрис переписан (`src/programs/game/tetris/main.c`)
- Механика: мешок из 7 фигур (каждая фигура раз в семь), вращение по SRS с отскоками от стен (отдельная таблица для I), вращение в обе стороны, фигура в запасе (hold, раз за фигуру), очередь из трёх следующих, тень места падения, задержка фиксации 500 мс с 15 сбросами при движении, два скрытых ряда над полем. Очки: 100/300/500/800 за 1–4 линии с множителем уровня, комбо, 1 за клетку мягкого и 2 за клетку жёсткого сброса. Уровень каждые 10 линий, скорость падения от 1000 до 5 мс по таблице. - Управление: стрелки или WASD, Up/X/W вращение, Z обратно, Space жёсткий сброс, Down/S мягкий, C hold, P или Esc пауза (Esc больше не закрывает окно), R заново, M звук, Q выход. Звуковые эффекты прежние.

### Время: RTC в UTC + часовой пояс с летним временем, страница «Time and region» в установщике, новый экран входа
- Часовые пояса (`src/kernel/time/tz.c`, `tz.h`): таблица из 56 зон (UTC, Европа, Америка, Азия, Австралия, Новая Зеландия) и правила летнего времени EU, US, AU, NZ. `make test-tz` (`tests/tz_test.c`) проверяет переходы 2026 года по минутам.
- Ядро (`src/kernel/time/wallclock.c`): CMOS по-прежнему хранит UTC. Пояс читается из `/etc/timezone` сразу после монтирования корня, `wallclock_tz_minutes()` отдаёт смещение с учётом летнего времени (его и видят `SYS_TIME_GET` и `localtime` в libc). Новый syscall 395 `SYS_TIME_ZONE` (0 получить имя пояса, 1 поставить: только root, пишет `/etc/timezone`), обёртки `pc_time_zone_get`/`pc_time_zone_set`. `wallclock_set_utc` ставит время, не трогая пояс; `SYS_TIME_SET` с другим смещением сбрасывает именованный пояс в фиксированный.
- Установщик (`src/programs/installer/`): новый шаг «Time» между «Computer» и «Account» (7 шагов в боковой панели). Список поясов с городом, смещением и текущим временем в каждом, прокрутка колесом и стрелками, сверху большие часы выбранного пояса, дата, пометка летнего времени и время UTC; обновление раз в секунду. Выбор попадает в `install_account_request.timezone`, ядро при установке пишет `/etc/timezone` на целевой диск и сразу включает пояс. В сводке перед установкой есть строка «TIME ZONE».
- Часы C-стола (`src/userspace/apps/datetime_service.c`): больше не ведут собственное время из `/purec/datetime.cfg`, а берут его из ядра (RTC + пояс). Установка времени из часов или календаря пишет в RTC в UTC.
- Экран входа (`src/programs/login/main.c`): окно без рамки (раньше были заголовок «PureC OS - Login» и кнопки свернуть и закрыть), большие часы и дата над карточкой, карточка входа по размеру содержимого (у живой сессии больше нет пустого места), кнопка «Sign in» или «Enter», подсказка внизу. Часы перерисовываются раз в минуту.
- libgui: `pg_window_set_frameless()` (окно без заголовка и рамки, клиентская область равна окну, без перетаскивания). Флаг лежит в байте выравнивания `struct pg_window`, размер (172 байта) и смещения полей не менялись, SDL и Qt-плагин пересобирать не нужно.
- Проверено: `make kernel`, `make libraries`, программы, `test-tz`, `test-civil`, `test-install-accounts`, `test-accounts`. В ВМ и на железе не запускалось.

### Батарея на железе, тачпад ELAN (ASUE1411), индикатор батареи в Rust-столе, чёрный фон консоли логов
- EC (`acpi/src/acpi_ec.c`): обработчик региона EmbeddedControl ставится сразу после `uacpi_namespace_load`, до `uacpi_namespace_initialize`, поэтому `_INI`, `_STA` и `_REG` уже видят EC. Порты EC берутся из `_CRS` устройства PNP0C09 (раньше только из ECDT или 0x62/0x66); если порт статуса читается как 0xFF, обработчик не ставится. Транзакции закрыты спинлоком. Очередь событий EC (SCI_EVT, команда 0x84) разбирается при опросе батареи с вызовом методов `_Qxx`, чтобы прошивка не застревала на неразобранных событиях. Таймауты EC пишутся в лог (первые 8).
- Батарея (`acpi/src/acpi_battery.c`): узел ищется один раз и кэшируется (раньше на каждый запрос обходилось всё пространство имён с вызовом `_BIF` на каждом устройстве). Сначала спрашивается `_BIX`, потом `_BIF`. Значения 0xFFFFFFFF считаются неизвестными: при неизвестной полной ёмкости берётся проектная. Отсутствие батареи определяется по биту 4 `_STA`. Ток в мА пересчитывается из мВт при единицах mWh. Время до разряда и до полного заряда. Результат кэшируется на 2 с. В лог пишется только изменение процента или зарядки, с сырыми `state`, `rem`, `full`, `rate` и единицами.
- Тачпад (`src/drivers/input/i2c_hid_touchpad/`, `acpi/src/acpi_sensors.c`): устройства ACPI теперь читают `_CID`. ASUE1411 имеет PNP0C50 только в `_CID`, поэтому раньше драйвер его не находил вообще. Пропускаются устройства с `_STA`, где не выставлены present и enabled. Каждый кандидат пишется в лог. Для I2C-контроллера: `_PS0` на ACPI-узле, перевод PCI-функции в D0 через PMCSR, тайминги SCL и SDA hold из ACPI-методов `SSCN` и `FMCN` (как в Linux), при их отсутствии остаются старые расчётные. Пауза после SET_POWER ON увеличена с 2 до 60 мс.

### POSIX-примитивы для порта Qt 6: события, Unix-сокеты, общая память, `sigaltstack` (`src/kernel/ipc/`, `src/mm/shm.c`, `src/libc/`)
- `eventfd`, `timerfd` и `epoll` (syscalls 380-386, `src/kernel/ipc/evfd.c`): один новый тип описателя в `ofd`. `eventfd` со счётчиком и `EFD_SEMAPHORE`; `timerfd` считает срабатывания лениво по `timer_ticks()` (одноразовый и периодический, `gettime`, снятие), без ядерных таймеров; `epoll` поверх того же опроса, что и `poll`: `EPOLL_CTL_ADD/MOD/DEL`, уровневый режим, `EPOLLET`, `EPOLLONESHOT`, `EPOLLRDHUP`, вложенный `epoll` (до 2 уровней), закрытые в процессе описатели сами выпадают из набора, а `epoll` не держит ссылок на `ofd`, поэтому закрытый конец канала по-прежнему даёт EOF читателю. В libc: `sys/epoll.h`, `sys/eventfd.h`, `sys/timerfd.h`, `struct itimerspec` в `time.h`.
- Unix-сокеты (syscalls 387-389, `src/kernel/ipc/unix.c`): `socketpair`, `socket(AF_UNIX, SOCK_STREAM)`, `bind` по пути (создаёт узел в VFS, занятый путь даёт `EADDRINUSE`), abstract-имена (`\0имя`) и автопривязка, `listen`, `connect` (`ENOENT` без файла, `ECONNREFUSED` без слушателя), `accept`/`accept4`, `getsockname`/`getpeername`, `shutdown`, `MSG_PEEK`, `MSG_DONTWAIT`, `MSG_NOSIGNAL`, `SIGPIPE`/`EPIPE`, `SO_PEERCRED`, `poll` и `epoll` (`POLLHUP` при закрытии пира). У каждого конца кольцевой буфер на 16 КиБ, блокировка с пробуждением, как у `pipe`.
- `sendmsg`/`recvmsg` (в том числе для TCP-сокетов, по `iovec`) с `SCM_RIGHTS`: до 16 описателей в сообщении, `MSG_CTRUNC` при нехватке места в управляющем буфере, `MSG_CMSG_CLOEXEC`. Описатели привязаны к первому байту сообщения, чтение не переходит границу сообщения с другим набором описателей, недоставленные описатели закрываются вместе с сокетом. В libc: `sys/uio.h` (`iovec`, `readv`, `writev`), `msghdr`, `cmsghdr`, `CMSG_*`, `ucred`, `SO_PEERCRED`, настоящий `socketpair`.
- Общая память между процессами (`src/mm/shm.c`, `vma.c`, `vmm.c`): объект `shm` (страницы по требованию, двухуровневая таблица до 1 ГиБ, счётчик ссылок), `mmap(MAP_SHARED | MAP_ANONYMOUS)` теперь действительно общая и после `fork`, `memfd_create`, `shm_open`/`shm_unlink` (именованный реестр, `O_CREAT`, `O_EXCL`, `O_TRUNC`), `ftruncate` и `fstat` для них, отображение со смещением, передача `memfd` через `SCM_RIGHTS` (сценарий Wayland). Запись VMA хранит `shm` и смещение; ссылки считаются при разрезании, слиянии, клонировании таблицы и уничтожении. В записи таблицы страниц новый программный бит `VMM_PAGE_SHARED` (бит 52): `fork` такие страницы не превращает в COW, своп их не трогает, `mprotect` бит сохраняет. `SYS_MMAP` принимает расширенную структуру с `fd` и `offset` (старая 32-байтовая форма читается как прежде).
- `madvise(MADV_DONTNEED)` теперь реально освобождает страницы (syscall 393): у приватных анонимных областей следующее обращение даёт нули, у общих данные сохраняются. Остальные советы принимаются и игнорируются, `MADV_*` приведены к значениям Linux.
- `sigaltstack` (syscall 394): у `struct thread` поля `altstack_sp`/`altstack_size`; `SA_ONSTACK` переключает доставку сигнала на альтернативный стек (вложенный сигнал не сбрасывает стек), `SS_ONSTACK`/`SS_DISABLE`, `EPERM` при смене стека изнутри обработчика, `ENOMEM` при размере меньше 2048. Стек из `mmap` подкачивается при доставке сигнала, поэтому ловится переполнение обычного стека.
- `dlopen`: гостевой тест `/bin/dltest-dyn` с библиотеками `/lib/libdltest.so` и `/lib/libdltest2.so` (собираются при `PUREC_DYNAMIC=1`): `dlopen(NULL)`, ошибки через `dlerror`, `RTLD_LAZY`/`NOW`/`GLOBAL`/`LOCAL`/`NOLOAD`, конструктор и деструктор, повторный `dlopen` и счётчик ссылок `dlclose`, вызов `libpurec.so` через PLT, обратный вызов в исполняемый файл, символ из исполняемого файла в библиотеке, зависимость `DT_NEEDED`, `dladdr`, `dl_iterate_phdr`.

### Новая модель памяти: ленивый `mmap` (VMA), подкачка страниц по обращению (`src/kernel/process/vma.c`, `process.c`, `src/mm/`)
- `mmap` больше не выделяет и не обнуляет страницы сразу: он только записывает область в таблицу VMA процесса (`src/kernel/process/vma.c`: отсортированный массив областей с защитой, разрезание и слияние при `munmap`/`mprotect`/`MAP_FIXED`, поиск свободного места первым подходящим). Страница выделяется при первом обращении в обработчике #PF (`process_handle_lazy_fault`): учёт `oom_gate` ведётся на страницу, а не на весь `mmap`, область `PROT_NONE` (резерв адресного пространства, в том числе десятки гигабайт) ничего не стоит. Выделение атомарно (`vmm_map_zero_page` не заменяет уже отображённую страницу), поэтому одновременное первое обращение из нескольких потоков не теряет данные; после отображения VMA перепроверяется, на случай гонки с `munmap`/`mprotect`.
- `munmap`, `mprotect`, `mremap` работают поверх VMA: `mprotect` по резерву `PROT_NONE` просто меняет защиту, а страницы появятся при обращении; участки вне VMA (сегменты ELF) обрабатываются по-старому. `mremap` переносит только присутствующие страницы.
- Ядро читает и пишет ещё не тронутые страницы пользователя сам: `process_user_buffer` подкачивает недостающие страницы перед проверкой доступа, а ошибка страницы в режиме ядра на пользовательском адресе тоже обрабатывается.
- При нехватке памяти ошибка страницы не завершает процесс сразу: обработчик ждёт до 3 с, пока OOM-киллер освободит память (вытеснение в swap, затем убийство самого большого процесса), если процесс сам жертва, он завершается по `SIGKILL`, и по `SIGKILL`, а не по `SIGSEGV`, он завершается и когда страницы так и не дождался (запись «oom: pid=… got no page … killed» в журнале). `fork` копирует таблицу VMA, `execve` и освобождение процесса её уничтожают.
- Память процесса возвращается в момент завершения (`process_release_memory` в `process_terminate`: переход на адресное пространство ядра, уничтожение пользовательского, снятие учёта и таблицы VMA), а не при `waitpid` родителя. Раньше убитый OOM-киллером процесс оставался зомби с занятой памятью, пока родитель не вызывал `waitpid`, и киллер почти не освобождал память.
- Личный потолок процесса 512 МиБ убран (теперь ограничивает только общий резерв памяти). Куча `brk` пока выделяется страницами сразу.
- Тесты: `make test-vma` (200 000 случайных операций над таблицей VMA против простой модели, под ASan и UBSan) и гостевая `/usr/bin/memtest` (ленивость 1 GiB, обнулённые страницы, резерв 64 GiB `PROT_NONE`, `munmap` с дырой, `mprotect`, `fork` с COW, `read`/`write` в нетронутые страницы, `mremap`, гонка первого обращения из 8 потоков, утечки).

### Доработки потоков: `errno` по потокам, блокировки `stdio`, семафоры, OOM-киллер (`src/libc/`, `src/mm/oom/`, `src/kernel/process/`)
- `errno` стал потоковым: `errno.h` определяет `errno` как `(*__errno_location())`, у каждого потока своё поле в `struct pthread`; до настройки TLS (программы без `crt0`) функция отдаёт старый глобальный `errno`, он по-прежнему определён в `stdlib.c` для заранее собранных объектов. Хостовый тест `malloc` собирается с `-Derrno=pc_errno`, заголовок это учитывает.
- `stdio`: у каждого `FILE` своя рекурсивная блокировка (включается после первого `pthread_create`, как у `malloc`), реестр открытых файлов под отдельной блокировкой; обёрнуты `fflush`, `fclose`, `freopen`, `fseek`, `ftell`, `rewind`, `fgetc`, `fgets`, `fputc`, `fputs`, `ungetc`, `fread`, `fwrite`, `clearerr`, `setvbuf`, `vfprintf` (а значит и `printf`/`fprintf`). Блокировка пофайловая, поэтому блокирующее чтение `stdin` не задерживает вывод в `stdout`.
- `pthread`: `pthread_getattr_np`, `pthread_attr_getstack` (нужны сборщикам мусора для границ стека), `pthread_sigmask`, `pthread_kill` (сигнал уходит процессу, не конкретному потоку), `pthread_mutex_timedlock`, заглушки `pthread_cancel`/`setcancelstate`/`setcanceltype`/`testcancel`; `semaphore.h` и `sem_*` на futex.
- OOM-киллер подключён: `oom_victim_kill_one` раньше не вызывался нигде, а «киллер» только подчищал зомби. Теперь, когда `oom_gate_try_charge_user` отказывает из-за нехватки памяти (свободных страниц не больше удвоенного резерва для запроса больше 4 страниц, либо не больше самого резерва), ядро сначала синхронно вытесняет страницы в swap (`vmm_swap_reclaim`, если раздел включён и не заполнен), затем запускает освобождение (`oom_reclaim_try`), и только если памяти всё ещё нет, выбирает жертву (процесс с наибольшим числом страниц, кроме `init` и служебных) и отправляет ей `SIGKILL` через новую `signal_send_kernel` (без проверки uid). Между убийствами пауза 1,5 с, в журнал пишется «oom: pid=… starved, kill victim pid=…». Превышение личного потолка процесса (512 МиБ) по-прежнему просто отказ без убийства.
- `thrtest` получил проверки `errno` по потокам, `printf`/`fprintf` из 4 потоков в один файл, семафора и `pthread_getattr_np`; новая программа `memhog` (`/usr/bin/memhog`: один процесс, `fork N`, `threads N`) для нагрузки памяти.

### Потоки и TLS: `clone`-подобные потоки, `futex`, `FS_BASE`, настоящий `pthread` (`src/kernel/process/`, `src/libc/pthread.c`)
- Ядро: у `struct thread` появились `fs_base`, `clear_child_tid` и собственный кадр входа в ring 3. `finish_switch` пишет `FS_BASE` входящего пользовательского потока при каждом переключении (в `user.asm` убрана загрузка `fs`, она обнуляла базу), `fork` наследует `FS_BASE` вызвавшего потока, `execve` сбрасывает его. Новые syscall: `SYS_THREAD_CREATE` 375 (структура `kernel_thread_args`: точка входа, стек, аргумент, база TLS, адрес `clear_tid`), `SYS_THREAD_EXIT` 376 (стирает слово `clear_tid`, будит ожидающих, при необходимости снимает со своего же стека отображение), `SYS_FUTEX` 377 (`FUTEX_WAIT` с таймаутом и `FUTEX_WAKE`, очередь ожидающих в `futex.c`), `SYS_SET_FS_BASE` 378, `SYS_GETTID` 379. В планировщике добавлены `scheduler_block_timeout`, `scheduler_wake_process_threads`, `scheduler_create_sibling_thread`.
- Модель процесса с несколькими потоками: `process->extra_threads`, `exit_group`, `exit_tid`. `exit`, фатальный сигнал и `execve` останавливают остальные потоки процесса: они будят всех соседей и ждут, пока те умрут на границе возврата в ring 3 (после syscall и по таймерному прерыванию), блокирующие вызовы выходят по `signal_pending_current` (оно теперь учитывает `exit_group`). `waitpid` и `oom_reap` считают процесс зомби только когда остановлены все потоки. Завершение дочернего процесса будит и поток, ждущий в `waitpid` (через `child_waiter_tid`), а не только главный.
- libc: настоящий `pthread` вместо заглушек из `compat.c`: `pthread_create/join/detach/exit/self`, атрибуты (размер стека, guard, detach), мьютексы (обычный, рекурсивный, errorcheck) на futex, `pthread_cond_*` (включая `timedwait`), `pthread_once`, ключи с деструкторами (`pthread_key_*`), `pthread_rwlock_*`, `sched_yield`, `__cxa_thread_atexit_impl`, `sched.h`. Стек потока создаётся через `mmap` с guard-страницей, TLS-блок и `struct pthread` лежат над стеком; отдельный поток без `join` освобождает свою область сам через `SYS_THREAD_EXIT`.
- TLS: `linker-userspace.ld` получил `.tdata` и `.tbss` (линкер создаёт `PT_TLS`), `crt0` устанавливает TLS главного потока до конструкторов (модель x86-64 variant II, `%fs:0` указывает на `struct pthread`, под `%fs:0x28` оставлено место для канарейки). Программы с собственным `_start` (без `crt0`) получают TLS лениво при первом вызове `pthread_*`.
- `malloc`/`free`/`realloc`/`aligned_alloc` защищены рекурсивной блокировкой, которая включается только после первого `pthread_create` (однопоточные программы не платят за неё). `tests/malloc_test.c` получил заглушки блокировки.
- Тест в госте: `/usr/bin/thrtest` (`src/programs/thrtest/main.c`): `__thread`-переменные с `.tdata` и `.tbss`, изоляция TLS между потоками, мьютекс на 4 потока, condvar (wake и timeout), detached-поток, `pthread_once`, ключи с деструктором, `malloc` из 4 потоков, TLS после `fork`, `exit` убивает вращающиеся и спящие соседние потоки, `exit` из не-главного потока.
- Ограничения: `errno` по-прежнему общий на процесс; динамически загружаемые `.so` с TLS (`PT_TLS` в загрузчике) и `stdio` без блокировок для нескольких потоков; `pthread_cancel`, `pthread_kill` и сигналы на конкретный поток не реализованы.

### Новый аллокатор памяти libc (`src/libc/malloc.c`, `src/libc/stdlib.c`, `src/libc/Makefile`)
- Старый `malloc` искал блок линейным обходом всего списка, а `free` после каждого вызова обходила весь список в `malloc_coalesce()`: сложность росла квадратично с числом блоков. NetSurf (сотни тысяч мелких объектов DOM и CSS) упирался в это: в профиле по 80 замерам `rip` 78 пришлись на `malloc` и `free`, Википедия не загружалась за две минуты. Теперь аллокатор граничных тегов: заголовок 16 байт с флагами занятости, слияние соседей за O(1), 256 списков по размерам (точные до 1 КБ, дальше по 4 на степень двойки), битовая карта непустых списков, арены 256 КБ, `realloc` растёт на месте за счёт соседнего свободного блока, добавлен `malloc_usable_size`. Старый код удалён из `stdlib.c`. Стресс-тест на хосте: 3 миллиона случайных `malloc`/`calloc`/`realloc`/`free` с проверкой содержимого каждого блока, выравнивание 16 байт, после освобождения блок в 20 МБ укладывается в уже занятую память. Коснулось всех программ.

### BSD-сокеты: сокет как обычный файловый дескриптор, DNS из userspace, `httpget` (`src/net/api/socket.[ch]`, `src/net/transport/tcp.[ch]`, `src/kernel/process/ofd.[ch]`, `src/kernel/process/fdtable.[ch]`, `src/kernel/syscall/`, `src/libc/socket.c`)
- Ядро: новый вид открытого файла `OFD_SOCKET`. Сокет создаётся системным вызовом `SYS_SOCKET` (362) и живёт в таблице дескрипторов процесса, поэтому `read`/`write`/`close`/`dup`/`dup2`/`fcntl(O_NONBLOCK)`/`poll`/`select` работают с ним как с любым fd, а `fork` и `exec` наследуют его. Закрытие последнего дескриптора закрывает TCP-соединение; при завершении процесса сокеты закрываются вместе с таблицей дескрипторов.
- Новые вызовы 362–373: `socket`, `connect`, `bind`, `listen`, `accept` (с флагами `SOCK_NONBLOCK`/`SOCK_CLOEXEC`), `shutdown` (`SYS_SOCK_SHUTDOWN`, половинчатое закрытие через FIN), `getsockname`/`getpeername`, `setsockopt`/`getsockopt` (`SO_RCVTIMEO`, `SO_SNDTIMEO`, `SO_ERROR`, `SO_TYPE`, `SO_REUSEADDR`, `SO_KEEPALIVE`, `TCP_NODELAY` принимаются, остальное даёт `ENOPROTOOPT`), `send`/`recv` с `MSG_DONTWAIT`, и `SYS_DNS_RESOLVE` (имя в IPv4, повторяет запрос, пока DNS занят). Блокирующие операции ждут по одному тику планировщика и прерываются сигналом (`EINTR`), раньше ожидание в TCP сигналы не замечало. Неблокирующий `connect` возвращает `EINPROGRESS`, готовность видна в `poll` как `POLLOUT`, результат в `SO_ERROR`.
- TCP: добавлены `tcp_bind`, `tcp_shutdown_write`, `tcp_readiness` (читаемость, записываемость, ошибка, обрыв, ожидающий `accept`) и `tcp_pending_error`; число одновременных TCP-сокетов увеличено с 16 до 32. Коды ошибок TCP переводятся в `errno` (`ECONNREFUSED`, `ECONNRESET`, `ETIMEDOUT`, `ENETUNREACH`, `EADDRINUSE`, `EPIPE` и т.д.), добавлены константы ядра `KERR_*` и заголовок `errno.h` до 115.
- libc: `src/libc/socket.c` и заголовки `sys/socket.h`, `netinet/in.h`, `netinet/tcp.h`, `arpa/inet.h`, `netdb.h` (в `manifest.txt`). Есть `socket`/`connect`/`bind`/`listen`/`accept`/`accept4`/`shutdown`/`send`/`recv`/`sendto`/`recvfrom`/`getsockname`/`getpeername`/`setsockopt`/`getsockopt`, `htons`/`ntohs`/`htonl`/`ntohl`, `inet_aton`/`inet_addr`/`inet_ntoa`/`inet_pton`/`inet_ntop`, `getaddrinfo`/`freeaddrinfo`/`gai_strerror`/`getnameinfo`, `gethostbyname`, `getservbyname`. Только IPv4 и TCP; `socketpair` и UDP-сокеты возвращают ошибку, `getaddrinfo` отдаёт один адрес.
- Лимиты как в Linux: TCP-сокеты больше не лежат в статическом массиве из 32 штук, а выделяются по требованию (до 16384, буферы 2×16 КБ на сокет, память после освобождения переиспользуется), дескрипторов на процесс 1024 (было 64), открытых файловых описаний 16384, `FD_SETSIZE` и `poll` до 1024.
- `/usr/bin/httpget host [путь] [порт]`: разбор имени, неблокирующий `connect` с `poll`, `SO_ERROR`, `getsockname`, запрос `GET`, чтение ответа до закрытия. Это проверка нового слоя целиком.

### Журнал ядра с сохранением между перезагрузками и `journalctl` (`src/kernel/diagnostics/journal.[ch]`, `src/programs/journalctl/`, `src/kernel/diagnostics/klog.[ch]`, `src/drivers/power/power.c`, `src/kernel/core/init.c`)
- Раньше `/kernel.log` обнулялся при каждой загрузке (`SYS_FILE_WRITE` с пустым содержимым в потоке `kernel-log`), поэтому после перезагрузки старый лог пропадал. Новый поток `journal` читает кольцо `klog` через `klog_read_since`, переводит строки в структурированные записи `<boot_id> <unix> <uptime_us> <уровень> <cpu> <сообщение>` и дописывает их в `/var/logs/journal.log`. Размер файла ограничен 4 МБ, при превышении выполняется ротация до `journal.5.log` (пять архивных файлов). Записи не теряются между загрузками: каждая загрузка получает случайный идентификатор и маркер `boot-start`. Время записей считается как `unix_времени_загрузки + uptime` из самой строки `klog`, поэтому записи ранней загрузки получают верное время.
- Аварийное завершение: при `reboot`/`poweroff` (`power_reboot`/`power_shutdown`) журнал сбрасывает остаток и пишет маркер `clean-shutdown`. На следующей загрузке по хвосту файла определяется, было ли завершение чистым; если нет, в журнал попадает предупреждение «previous boot XXXXXXXX ended without a clean shutdown (crash, reset or power loss)». Это же косвенно ловит triple fault и потерю питания.
- Живая сессия (корень в initramfs) журнал не пишет: `/var` там в памяти.
- `journalctl`: `-b [N|ID]` (0 — текущая загрузка, -1 — предыдущая, 1 — первая), `--list-boots`, `-p debug|info|warn|err`, `-n N`, `-g TEXT`, `--since`/`--until` (`90s`, `10m`, `2h`, `1d` или unix-время), `-o short|short-monotonic|cat`, `-f` (с переживанием ротации), `-D DIR`. Читает `journal.N.log` от старых к новым.
- Ограничения MVP: пишется только ядро (`kernel[cpuN]`), нет вызова `syslog()` из userspace, нет записи при панике (обработчик паники не трогает VFS, чтобы не зависнуть на занятом мьютексе), нет бинарного формата и индексов. Между записью и сбросом на диск до 500 мс данных находятся только в памяти.
- Проверено: ядро собирается (3703 символа из 4096), `journalctl` собирается для ОС. Логика журнала (разбор строк `klog`, формат записей, неполные строки на границе чтения, ротация, определение аварийного завершения) прогнана на хосте под ASan/UBSan с заглушками VFS; `journalctl` проверен на хосте на журнале из двух загрузок (все ключи, коды ошибок, `-f` с усечением файла). В VM ещё не запускалось.

### Паники «unbalanced preempt enable» и «mutex: invalid owner»: гонки при определении текущего ядра и потока (`src/kernel/process/scheduler.c`, `src/kernel/process/scheduler.h`)
- Ядро падало с `sched: unbalanced preempt enable` в `scheduler_preempt_enable()` (сначала в `userspace_input_thread` → `window_manager_has_focus` → `wm_leave` при наборе C-программы во Vim, затем в `rs_session_input_thread` → `display_mode_poll` → `ext2_*` → `block_run` → `io_dev_unlock`). По дампам памяти VM на одном ядре оставалась лишняя единица `preempt_depth` (`cpu0 depth=1`, `reschedule_pending=1`, замки `wm_lock` и `comp_lock` свободны), а на паникующем ядре счётчик был равен 0.
- Причина: `scheduler_preempt_disable()`, `scheduler_preempt_enable()` и `scheduler_yield()` определяли номер ядра и брали указатель на его `struct scheduler_cpu` до `irq_save()`, то есть при включённых прерываниях. Таймерное прерывание в этом окне переносило поток на другое ядро, и счётчик менялся не на том ядре: на старом оставалась утечка, на новом `enable` приходился на нулевой счётчик. Теперь `irq_save()` выполняется первым, а номер ядра и счётчик берутся уже под ним, поэтому поток не может смениться ядро между чтением и изменением.
- Тот же шаблон давал панику `mutex: invalid owner` в `mutex_unlock()` (`net_service_thread` → `tcp_poll`): `scheduler_current_thread()` читал номер ядра при включённых прерываниях и только потом брал `cpu_schedulers[id].current`. Если поток переезжал между этими двумя действиями, функция возвращала чужой поток, и `caller()` в мьютексе записывал в `owner` чужой tid (в дампе `tcp_lock.owner` принадлежал потоку 11, который в это время спал в `syscall_handler` и замок не держал). Теперь номер ядра и `current` читаются под `irq_save()`.
- Счётчик вытеснения стал свойством потока: `struct thread` получила поле `preempt_saved`, `schedule_locked()` сохраняет счётчик уходящего потока и загружает счётчик входящего. Поток, заснувший внутри секции с выключенным вытеснением, больше не портит счётчик чужого ядра. Новые потоки (в том числе потомки `fork`) стартуют с нулём.
- В `scheduler_sleep()` и `scheduler_block()` добавлено предупреждение `sched: blocking with preemption disabled` с тремя адресами вызова (имена через `ksym`; не более 16 раз за запуск, повторный вход защищён), чтобы находить код, который блокируется под выключенным вытеснением. Пока предупреждение в логах не появлялось.
- Исправление гонки проверено только компиляцией `scheduler.c`; повторный прогон сценария в VM ещё не выполнен.

### Иконки приложений на столе (`assets/icons/`, `mk/gen_icons.py`, `src/userspace/apps/desktop_icons.c`)
- Для 18 приложений добавлены иконки Material Symbols (Rounded, заливка, Apache 2.0): один набор и один вес, поэтому стиль цельный. Исходники `.svg` и соответствие «приложение → иконка» лежат в `assets/icons/` (файл `NOTICE`).
- `mk/gen_icons.py` растеризует SVG в маски прозрачности `.icn` (`PCIC`, 96×96, 8 бит); `.icn` ставятся в `/usr/share/icons/` через `assets/manifest.txt`. Каждый `.desktop` получил строку `Icon=/usr/share/icons/<имя>.icn`.
- Стол загружает маску, масштабирует её под размер плитки (усреднением) и красит в цвет, контрастный к цвету плитки (тёмная на светлых, светлая на тёмных, терминал больше не пустой). Один блит на иконку через новый `gop_draw_pixels`. Нет файла или битый заголовок: рисуется прежний текстовый символ.

### Иконки рабочего стола: сетка и привязка (`src/userspace/apps/desktop_entries.c`, `src/userspace/userspace.c`)
- Размер иконки, плитки, символа и подписи считается от размера шрифта персонализации (`58*px/8` по ширине, `72*px/8` по высоте), так что при 12 px и больше подписи не налезают друг на друга. Длинные подписи обрезаются до `..` под ширину ячейки и центрируются под плиткой.
- Иконки раскладываются по сетке сверху вниз по столбцам; сетка пересчитывается при смене шрифта или разрешения, если ячейка вышла за экран, иконка занимает ближайшую свободную.
- Во время перетаскивания иконка свободно идёт за курсором, а на месте, куда она встанет, рисуется рамка. При отпускании иконка занимает ближайшую свободную ячейку (занятую ячейку не перетирает).
- Раскладка сохраняется в `/config/desktop.ini` (`id=колонка,строка`) и читается при запуске.

### Размер шрифта терминала и масштаб интерфейса (`src/drivers/display/gop.c`, `src/userspace/display_mode.c`, Settings)
- Консоль ядра больше не привязана к ячейке 8×10: размер ячейки (`cell_w`, `cell_h = cell_w*10/8`) берётся из `font_size` персонализации (8–24 px) и запоминается в слоте консоли при настройке. Терминал, который сконфигурирован после смены размера (новое окно или перенастройка при ресайзе), рисует крупным шрифтом, число строк и столбцов пересчитывается, `winsize` в tty отдаёт реальные размеры.
- Масштаб интерфейса: `gop` хранит физический размер экрана и рациональный масштаб (100–400%); приложения видят логический экран, а при выводе в видеопамять строки растягиваются (`write_scaled_span`, `gop_front_notify` для SVGA). Параметр `scale=` в `/config/display.ini`, применяется на лету вместе со сменой режима. `SYS_DISPLAY_SET_MODE` принимает масштаб четвёртым аргументом, новый `SYS_DISPLAY_SCALE_INFO` (361) отдаёт физический размер и масштаб. В Settings → Display добавлена карточка «Interface scale».
- Окна libgui возвращаются в границы экрана при перерисовке после смены режима или масштаба (`pg_window_fit_display`).

### Новый установщик: графический мастер (`src/programs/installer/`)
- Установщик полностью переписан: вместо консольных вопросов — полноэкранное окно с карточкой по центру на градиентном фоне, боковой панелью шагов (Welcome, Disk, Computer, Account, Review, Install) и страницами мастера. Все шаги работают с клавиатурой (Tab, Enter, Esc, стрелки) и мышью (колесо прокручивает список дисков).
- Рисование идёт в собственный буфер (`ui.[ch]`): скруглённые прямоугольники и окружности со сглаживанием, градиенты, тени, текст через `gfx/text.h`; в окно уходят одним блитом только изменившиеся строки, так что без мерцания. Статичный фон и карточка запекаются один раз.
- Страницы (`view.c`): приветствие; список дисков с карточками (имя, модель, размер, тип SATA/IDE/USB, недоступные и read-only затемнены) и схемой разметки диска (EFI, система ext2, своп); имя компьютера с предпросмотром приглашения терминала; аккаунт (полное имя, имя пользователя подставляется из имени, пароль с индикатором надёжности и показом, подтверждение, отдельный пароль root по желанию); подтверждение со сводкой и флажком стирания диска; установка с процентами, анимированным индикатором и списком этапов; финал и страница ошибки с текстом причины.
- Проверки прежние: `install_account_*_valid`, имя пользователя не `root` и не с `_`, пароли должны совпадать. Хэширование и запуск установки (`pc_install_start_accounts`) без изменений, пароли стираются из памяти после запуска. Если установка уже идёт, мастер сразу открывает страницу прогресса.
- `setup.c` сведён к `setup_build_request()` и `setup_wipe()`, `progress.c` — к тексту ошибок. В `syscall.h` добавлен пропущенный `#include <stdbool.h>`.

### Мерцание окон: двойная буферизация в компоновщике (`src/gfx/compositor.c`)
- Приложение рисует окно тысячами вызовов (текст идёт по одному прямоугольнику на глиф), и любой другой `present` (heartbeat, таскбар, курсор) показывал недорисованную поверхность: «чистое окно, потом текст». Теперь между `begin_update` и `end_update` рисование идёт в задний буфер окна, а на `end_update` изменённая область одним копированием попадает в видимую поверхность и выводится на экран.
- Задний буфер выделяется при первом `begin_update`, синхронизируется с видимой поверхностью только если она менялась вне обновления; при росте окна освобождается и создаётся заново. Если памяти не хватило, окно работает как раньше (без буфера).
- Тест в `tests/compositor_test.c`: `present` во время обновления не показывает промежуточный кадр.

### Мышь в VirtualBox: абсолютный указатель (`src/drivers/mouse/vbox_mouse.[ch]`, `ps2_mouse.c`)
- Относительная PS/2-мышь расходилась с хостовым курсором, и он «просачивался» из окна VM. Новый драйвер находит устройство VMMDev (PCI `80EE:CAFE`), через порт ввода-вывода из BAR0 отправляет guest info и запрос `SET_MOUSE_STATUS` с `GUEST_CAN_ABSOLUTE | NEW_PROTOCOL`, затем в цикле опроса читает `GET_MOUSE_STATUS` и берёт позицию (`0..0xFFFF`), масштабируя её на текущее разрешение.
- Страница запроса выделяется ниже 4 ГиБ (порт принимает 32-битный физический адрес); одновременный опрос с разных ядер защищён флагом занятости.
- В `ps2_mouse.c` добавлены `mouse_set_absolute_mode()` и `mouse_handle_absolute()`: пока хост просит абсолютный режим, дельты PS/2 игнорируются, кнопки и колесо идут как раньше. Если VMMDev нет или запрос не прошёл, поведение прежнее.
- Вызов `vbox_mouse_init()` в `kernel.c` после инициализации MMIO, опрос из `ps2_mouse_poll()`.

### Видеодрайвер: смена режима и очистка экрана (`src/drivers/display/`, `src/userspace/display_mode.c`)
- Смена разрешения при активном VMware SVGA II (VirtualBox VMSVGA/VBoxSVGA) шла через порты VBE DISPI, которые SVGA игнорирует. Новый `svga_set_mode()` перепрограммирует регистры SVGA, проверяет `MAX_WIDTH/MAX_HEIGHT` и размер видеопамяти, заново отображает фреймбуфер и при отказе возвращает прежний режим; инициализация FIFO вынесена в `svga_fifo_reset()`. `display_mode_apply_low()` при активном SVGA использует его, режим всегда 32 бита (в `display.ini` значение приводится к 32).
- `gop_apply_live()` теперь заливает новый фреймбуфер цветом консоли и обновляет весь экран. Раньше мусор из видеопамяти копировался в backbuffer и оставался до экрана логина.
- Без VBE/SVGA (GOP на железе) живая смена разрешения невозможна: нужно задавать `resolution:` в Limine и перезагружаться.

### Компоновщик и Rust-сессия (`src/gfx/compositor.c`, `src/userspace/rs_session.c`)
- Сдвиг окна, `end_update` и `compositor_present` рисуют полосами по 32 строки и отпускают `comp_lock` между полосами, чтобы курсор и опрос мыши не ждали композита целого окна.
- Шлейф за перетаскиваемым окном: пиксели, нарисованные приложением со старыми координатами, оставались в поле тени за рамкой. Поле теперь очищается при следующем `begin_update` после сдвига или смены размера (`margin_dirty`). Тест в `tests/compositor_test.c`.
- Heartbeat Rust-сессии: интервал 100 → 250 мс, между полосами опрашивается мышь.

### Зависание после перетаскивания окна (`src/drivers/display/gop.c`)
- Взаимная блокировка на `console_lock`: терминал держал замок в `gop_console_write` и вызывал компоновщик, `scheduler_preempt_enable()` вытесняла поток с замком в руках, а `gop_console_translate()` из потока рабочего стола на том же ядре крутился на этом замке с выключенными прерываниями. Часы стола останавливались, курсор двигался. Теперь вытеснение отключается на время владения `console_lock`.

### Сборка и libgui
- `src/programs/Makefile`: целью по умолчанию стал `vim/alloc.o`, поэтому общая сборка не пересобирала программы. Добавлен `.DEFAULT_GOAL := all`.
- `pg_button()` рисует кнопку и без события: приложения, перерисовывающиеся по таймеру (например «Диски»), теряли кнопки.


### Подсистема IO (`src/io/`)
- Драйверы накопителей (`ahci`, `ata-pio`, `block_device`, `storage_probe`, Limine-блобы) переехали из `src/drivers/` в `src/io/storage/`; пути в `mk/main.mk`, `docs/drivers/` и include'ах обновлены, у `src/io` свой `Makefile`.
- Планировщик IO (`io_sched.[ch]`): фоновые массовые операции (`io_bulk_begin/end`) работают с QoS `BACKGROUND` и `io_throttle()` отдаёт устройство короткими порциями (всплеск 3 мс, пауза 1 мс), так что установка и свопинг не вешают интерфейс. Блокировка устройства `io_dev_lock/unlock` делится на куски по `IO_LOCK_CHUNK_SECTORS` (8) секторов.
- Счётчики `struct io_stats`: прочитанные и записанные сектора, сектора и паузы массовых операций, число конфликтов за блокировку.
- `block_device.c` переписан на эти примитивы; xHCI/EHCI: ожидание блокировки сначала уступает процессор, затем засыпает на 1 мс.

### Своп (`src/io/swap.[ch]`, `src/mm/vmm.c`)
- Раздел подкачки с заголовком `PURESWAP` (версия 1), слоты по странице 4 КиБ (8 секторов), до 512K страниц. Функции `swap_format/enable/probe`, `swap_alloc/dup/free`, `swap_read/write`, `swap_info_get`.
- Определение раздела по GPT type GUID (`swap_gpt_type_guid`) на любом блочном устройстве.
- vmm: страницы пользователя помечены `VMM_PAGE_ANON`; вытесненная страница хранит номер слота в PTE (`VMM_PAGE_SWAPENT`), page fault и обращения ядра к пользовательской памяти подкачивают её обратно. `fork` дублирует слоты (`swap_dup`), `munmap` и уничтожение адресного пространства освобождают их. Реестр адресных пространств нужен для вытеснения чужих страниц, есть `vmm_swap_pause/resume`.
- Демон `kswapd` (QoS `BACKGROUND`) просыпается раз в период и вытесняет страницы, когда свободной памяти меньше нижней границы, до верхней; границы выводятся из резерва OOM (не меньше 2048 страниц).
- Установщик: на ATA PIO и AHCI создаёт раздел подкачки в конце диска (1/8 диска, до 2 ГиБ, выравнивание 1 МиБ, GPT-имя «PureC Swap»), если для данных остаётся не меньше 1 ГиБ; заголовок пишется `swap_format`.
- Во время установки файловые syscall'ы других процессов отклоняются (`filesystem_syscall_acquire`), открыть файловую систему может только поток установщика.



## Процессная модель и порт GNU Make

- Настоящие `fork` (COW, счётчики ссылок на фреймы) и `execve` с `argv`/`envp`, `waitpid` с POSIX-статусом, сигналы (`kill`, `sigaction`, `sigprocmask`, доставка на выходе из syscall и по таймеру), рост пользовательского стека по page fault.
- Файловые дескрипторы на общих open-file-description: `dup`, `dup2`, `fork`, `execve` разделяют смещение; каналы, `FD_CLOEXEC`, `O_NONBLOCK`, `O_RDWR`, запись по смещению, `lseek`, `ftruncate`; `stdio` переписан поверх fd.
- Рабочий каталог процесса (`chdir`/`getcwd`), `SYS_WRITE` родных программ уважает редирект fd 1.
- Новый POSIX `sh` (`/usr/bin/sh`, `/bin/sh`); терминал выполняет команды через `sh -c`.
- libc: `posix_spawn`, `system`, `popen`, `pipe`, `fcntl`, `mkstemp`, `getpwnam`, `uname`, `getrlimit`, `umask` и другое (`src/libc/process.c`, `src/libc/posix.c`).
- Порт **GNU Make 4.4.1** (`src/make/`, исходники в `gnumake/`): запускается на PureC OS (`make --version`, разбор Makefile), `-j1`; выполнение рецептов ещё не подтверждено. Подробности в `ported-software.md`.
- Тесты: `proctest`, `forktest`, `tests/pmm_refcount_test.c`.

## libm: настоящая математика для портов

### Математика (`src/libc/libm.c`, `src/libc/math.c`, `include/hosted/math.h`)
- Раньше `sin`, `cos`, `log`, `exp` были только объявлены, а дробная `pow`
  возвращала NaN. Теперь в libc полный набор: `sin cos tan asin acos atan atan2
  sinh cosh tanh exp exp2 expm1 log log2 log10 log1p pow sqrt cbrt hypot`,
  `round rint nearbyint lround llround lrint llrint copysign fmax fmin fdim
  scalbn nan` и float-версии всех (`sinf`, `cosf`, `powf`, `atan2f`, ...).
- Реализация на x87 в расширенной точности (ядро хранит x87/SSE-состояние потока
  через `fxsave`), `sqrt` на SSE. Точность 1–2 ULP от glibc; степени с точным
  результатом (`pow(10, 15)`) считаются точно.
- `sin`/`cos`/`tan`: аргумент приводится по частям π/2 (около 160 бит) до 3,3·10⁹;
  дальше точность падает (приведение через `FPREM1` с 66-битным π).
- Исправлены старые функции `math.c`: `fmod` ошибался на экстремальных отношениях
  и терял знак нуля (теперь через `FPREM`, точно), `trunc(-0.5)` возвращал `+0`.
- Заголовок: константы `M_PI_2`, `M_SQRT2`, `M_LN2` и др., макросы `isnan`,
  `isinf`, `isfinite`, `signbit`, `fpclassify`.
- Тест `tests/libm_test.c` (`make test-libm`): сверка с glibc по ULP на сотнях
  тысяч значений, особые значения (±0, ±inf, NaN) для всех функций, точные
  степени, float-версии.



### Блит буфера пикселей в окно (`src/gfx/blit.[ch]`, композитор, libgui, libc)
- Новый syscall `SYS_FB_BLIT` (322): программа отдаёт готовый буфер ARGB/XRGB
  (`struct fb_blit_request`: указатель, шаг строки, размер, позиция, флаги), и
  композитор копирует его в поверхность своего окна одним вызовом, с обрезкой по
  границам и одним `present` на кадр (внутри `pg_window_begin/end` — вместе с
  остальной отрисовкой кадра). Раньше кадр можно было собрать только из
  сотен вызовов `SYS_DRAW_RECT`.
- Источник проверяется целиком (`blit_source_bytes`: шаг не меньше ширины,
  размеры до 16384, не больше 256 МиБ), затем `vmm_user_range_accessible`.
  Альфа-канал по умолчанию форсируется в непрозрачный (формат `0x00RRGGBB`
  работает как есть); флаг `FB_BLIT_KEEP_ALPHA` сохраняет альфу источника.
- `pc_fb_blit()` в libc и `pg_window_blit()` в PureGUI (координаты клиентской
  области, обрезка по её границам).
- `gltest` переписан: рендер в собственный буфер 480×360, один блит за кадр,
  `sinf`/`cosf` из новой libm, счётчик FPS и времени кадра.
- Тест `tests/blit_test.c` (`make test-blit`): обрезка со всех сторон, огромные
  размеры без переполнения, копирование с форсированием альфы и без, проверка
  границ источника.
- Ограничение: у окна один буфер на процесс, блит работает только когда окно уже
  зарегистрировано оконным менеджером (иначе `-2`).

### ext2 без заглушек (`src/fs/ext2/`)
- `ext2_delete`, `ext2_rename`, `ext2_move` раньше возвращали `-10`. Теперь это
  настоящие операции (`meta.c`): удаление файлов и пустых каталогов с освобождением
  блоков и inode, переименование в каталоге, перенос между каталогами с
  обновлением `..` и счётчиков ссылок, защита от переноса каталога внутрь себя
  и от удаления служебных inode.
- Владелец, группа и режим читаются и пишутся в inode (`ext2_meta_get/set`),
  включая 32-битные uid/gid через `uid_high/gid_high`.
- `ext2_append_file` с тестом на файле больше 12+256+256² блоков.
- Исправлена паника ядра на bare metal при персонализации после установки на ext2.
- Исправлены ошибки inode: смещение 24 — это `i_gid`, а не счётчик ссылок; код
  писал туда 1 и 2, и у всех файлов был gid=1, а `links_count` оставался 0
  (`e2fsck` считал такие inode удалёнными). Теперь счётчик ссылок на смещении 26
  (файл 1, каталог 2, корень 2), gid 0. Перезапись файла больше не сбрасывает
  режим в 0644: владелец, группа и права сохраняются.
- Тесты: `tests/ext2_meta_test.c` (`make test-ext2-meta`) — после удаления всего
  число свободных блоков возвращается к исходному; `tests/ext2_append_test.c`.

### Права доступа и пользователи (`src/fs/vfs_perm.c`, ядро, libc)
- Проверка rwx по владельцу, группе и остальным в open/create/mkdir/write/append/
  delete/rename/move; root обходит проверки. Новая ошибка `FS_ERROR_DENIED`.
  Новый файл получает владельцем создателя; `/tmp` и `/run` создаются с режимом 1777.
- Права хранятся в inode на ext2 (через `get_meta/set_meta` в `vfs_fs_ops`),
  на остальных ФС — в таблице в памяти.
- У процесса появились `uid` и `gid`, наследуются от родителя; сменить их может
  только root.
- Syscalls 309–318: `getuid`, `getgid`, `setuid`, `setgid`, `chmod`, `chown`,
  `file_perm`, `user_lookup`, `getrandom`, `session_begin`. Обёртки в libc:
  `pc_getuid`, `pc_chmod`, `pc_chown`, `pc_file_perm`, `pc_user_lookup`,
  `pc_getrandom`, `pc_session_begin`.
- Разбор `/etc/passwd` (7 полей) в `vfs_perm.c`; тест `tests/vfs_perm_test.c`.

### Драйвер случайных чисел (`src/drivers/random/`, `src/kernel/random/`)
- Модуль `random.so`: Hash_DRBG по SP 800-90A на `pure_sha512` из `libxcrypt`
  (`random_core.c`). Энтропия — RDRAND + джиттер TSC через SHA-512, reseed каждые
  4096 запросов и при записи в `/dev/random`.
- Фасад ядра `krandom.c` грузит модуль после `devman_autoload`, проверяет версию
  ABI; если модуля нет — запасной xorshift (в логе `random: fallback backend`).
- `/dev/random` и `/dev/urandom` читают из DRBG; новый syscall `SYS_GETRANDOM`.
- `devman_load_module()` — загрузка `.so`, не привязанных к устройству.
- Тест `tests/hdrbg_test.c` (`make test-hdrbg`): сверка с независимой реализацией
  на `hashlib`, включая reseed.

### Криптография вне ядра (`libxcrypt`, `mk/main.mk`)
- `libxcrypt` больше не линкуется в образ ядра (там он не использовался);
  собирается как библиотека `bin/lib/libpurecrypt.a` для `login` и установщика.
- Исправлена ошибка `purecrypt_verify`: соль, начинающаяся с `r`, принималась за
  префикс `rounds=` и корректный хеш отвергался (`-1`). Регрессия в `test_crypt.c`.

### Новый установщик (`src/programs/installer/`, `src/fs/install*.c`)
- Шаги: диск → имя компьютера → пароль root (дважды, ввод скрыт) → обычный
  пользователь (имя, полное имя, пароль) → сводка и подтверждение `ERASE`;
  на сводке `E` возвращает к настройкам.
- Пароли хешируются в ring 3 (`$6$`, соль из `getrandom`), в ядро уходят только
  хеши (`struct install_account_request` в `SYS_INSTALL_START_EX`).
- Ядро после копирования системы пишет `/etc/passwd`, `/etc/shadow` (0600),
  `/etc/group`, `/etc/hostname`, `/root` (0700) и `/home/<user>` (0700, владелец —
  пользователь). Запрос валидируется (`install_accounts.c`): имена, хеши, запрет
  `:` и переводов строк, пользователь не может быть `root`.
- Тесты: `tests/install_accounts_test.c`, `tests/accounts_test.c`.

### Экран входа (`src/programs/login/`, `src/programs/accounts/`)
- Поля имени и пароля (Tab, мышь, Enter), проверка по `/etc/shadow` через
  `purecrypt_verify`, растущая задержка после неудач.
- Успешный вход вызывает `SYS_SESSION_BEGIN`: программы, запускаемые от десктопа
  (root-родитель, кроме init), получают uid/gid пользователя.
- Без `/etc/shadow` (live-ISO) остаётся вход одной кнопкой как root.

### Часы и время (`src/kernel/time/`, libc)
- Раньше `time()` считал секунды от загрузки, десктопные часы жили в
  `/purec/datetime.cfg`. Теперь есть настоящие часы ядра: `rtc.c` читает CMOS RTC
  (ожидание конца обновления, двойное чтение до совпадения, BCD/двоичный
  режим, 12/24 часа, век), `wallclock.c` держит календарное время поверх
  аптайма TSC, `civil.c` — перевод даты в unix-время и обратно.
- В лог при загрузке: `time: RTC 2026-10-29 11:39:58 UTC` (сверено с хостом).
- Syscalls `SYS_TIME_GET` (319), `SYS_TIME_SET` (320, только root: ставит время и
  пишет его в RTC, плюс смещение пояса), `SYS_FILE_STAT_EX` (321: размер, режим,
  uid, gid, atime/mtime/ctime). Обёртки `pc_time_get`, `pc_time_set`,
  `pc_file_stat_ex`.
- Hosted libc: `time()`, `gettimeofday()`, новый `clock_gettime()`
  (`CLOCK_REALTIME`/`CLOCK_MONOTONIC`) читают календарное время; `localtime()` и
  `mktime()` учитывают пояс ядра (без летнего времени); `stat()` отдаёт
  `st_mode`, `st_uid`, `st_gid` и времена файлов.
- ext2 записывает atime/ctime/mtime при создании, записи, дозаписи и смене
  прав, время удаления — в `dtime`; tmpfs хранит времена своих узлов.
- Тест `tests/civil_test.c` (`make test-civil`): сверка с `gmtime_r` хоста на
  десятках тысяч дат, високосные годы (2000, 2100), граница 2038, разбор RTC во
  всех режимах и битые значения.

### Железо: ввод, USB, питание (`src/drivers/`, `src/kernel/smp/`)
- Новый драйвер I2C-HID тачпада (ELAN, Intel LPSS) с прерываниями в IDT.
- `cpufreq.c`: управление частотой процессора, HWP и EIST.
- xHCI: глобальная блокировка контроллера, таймауты по TSC вместо счётчика
  (частота из CPUID 0x15), восстановление зависшей конечной точки USB-мыши
  (Reset Endpoint + Set TR Dequeue). Исправляет лаги и пропадание мыши на
  bare metal (i5-1235U).
- Клавиатура: буферы обычных и специальных клавиш под IRQ-safe спинлоком.

### Wi-Fi AR9285 (порт ath9k, `src/drivers/net/ath9k/`)
- Аппаратный слой: регистры, initvals (`mk/gen_ath9k.py`), чтение EEPROM,

### Графика (`src/userspace/window_manager.c`)
- Оконный менеджер использует композитор: создание, поднятие, обновление и
  уничтожение окон проходят через `compositor_window_*`; окна, которыми уже
  занимается композитор, не получают лишних перерисовок.

### Сборка и инструменты
- `purec.py`: живой вывод по стадиям сборки; `db/builds.db` пополняется при каждой

- Права на не-ext2 файловых системах живут только в памяти; бит `x` и обход

- Сквозная установка с аккаунтами и вход под обычным пользователем проверены

### Планировщик: Apple-style QoS + кванты (`src/kernel/process/scheduler.[ch]`, `src/kernel/core/init.c`)

- Кванты по классу: interactive 2мс, initiated 3мс, default 5мс (= `SCHEDULER_TIME_SLICE_MS`),
  utility 8мс, background 10мс; `schedule_locked()` выставляет `ticks_remaining` по QoS потока.
- `pick_next()`: сначала максимальный QoS среди READY/eligible, внутри класса — старый
  round-robin по курсору. Когда все потоки DEFAULT — поведение 1-в-1 как было.
- `init-input`/`desktop-keyboard` → `USER_INTERACTIVE`, `net-rx` → `UTILITY`,
  `kernel-log`/`qemu-net-test` → `BACKGROUND`.
- Снят жёсткий пин `affinity 0` (BSP) у `init-input`, `desktop-keyboard`, `kernel-log`,
  `net-rx`, `qemu-net-test` → `affinity -1` (любой CPU). Было: драг окна дёргал только CPU0;
