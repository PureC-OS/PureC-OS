# Драйвер PCI (конфигурационное пространство, BAR, перечисление)

Базовый слой доступа к шине PCI через механизм Configuration Mechanism #1 (порты `0xCF8` адреса и `0xCFC` данных). Все остальные драйверы, которым нужно найти устройство или включить у него память и bus master, идут через эти функции. Драйвер не настраивает прерывания (MSI/MSI-X) и не поддерживает PCIe ECAM.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/pci/pci.h` | Структура `pci_device_info`, флаги команды, объявления функций |
| `src/drivers/pci/pci.c` | Реализация |

## Структуры и константы

`struct pci_device_info` содержит `vendor_id`, `device_id`, `bus`, `slot`, `function`, класс, подкласс, интерфейс программирования и ревизию.

Флаги команды (регистр `0x04`): `PCI_COMMAND_IO_SPACE` (bit 0), `PCI_COMMAND_MEMORY` (bit 1), `PCI_COMMAND_BUS_MASTER` (bit 2).

## Публичный API

| Функция | Что делает |
|---------|------------|
| `pci_enumerate(visitor, ctx)` | Обходит все шины 0–255, слоты 0–31 и функции 0–7 (если установлен бит multi-function). Для каждого найденного устройства вызывает `visitor` |
| `pci_read_config32(bus, slot, fn, off)` | Читает 32 бита из конфигурации |
| `pci_write_config32(bus, slot, fn, off, val)` | Пишет 32 бита |
| `pci_write_config8(...)`, `pci_write_config16(...)` | Пишут один или два байта. Запись 16 бит по нечётному смещению игнорируется |
| `pci_update_command(dev, set, clear)` | Меняет регистр команды, затем перечитывает и проверяет результат. Возвращает `false`, если биты не установились |
| `pci_read_bar(bus, slot, fn, index)` | Адрес BAR. Для 64-битных BAR собирает два регистра. Для IO-BAR возвращает адрес порта |
| `pci_bar_size(bus, slot, fn, index)` | Размер BAR методом записи всех единиц и чтения маски. Восстанавливает исходное значение |

Все функции, кроме `pci_enumerate`, берут спинлок `pci_lock` с сохранением флагов прерываний. `pci_enumerate` спинлок не берёт и обращается к портам напрямую. Поэтому его обход может перемешаться с параллельной записью конфигурации на другом ядре.

## Где используется

Драйверы, которые вызывают функции PCI (через `pci/pci.h`):

- Хранение: `storage/ahci.c`, `storage/block_device.c`, `storage/ata_pio.c`, `storage/storage_probe.c`. См. [AHCI](ahci.md).
- USB: `usb/xhci.c`, `usb/ehci.c`. См. [xHCI](xhci.md) и [EHCI](ehci.md).
- Сеть: `net/e1000`, `net/82543gc`, `net/pcnet`, `net/ath9k`.
- Аудио: `audio/audio_hda.c`.
- Дисплей: `display/vbe.c`, `display/svga.c`.
- Ввод: `input/i2c_hid_touchpad`.
- Прочее: `kernel/devices/device_manager.c`, `fs/`, `net/tests`.

## Внутреннее устройство

- Адрес конфигурации: `0x80000000 | bus << 16 | slot << 11 | fn << 8 | (offset & 0xFC)`.
- Чтение пустого слота возвращает `0xFFFF` в поле vendor ID, такие записи пропускаются.
- Функции 1–7 проверяются только если в заголовке функции 0 установлен бит multi-function (`0x80`).
- Обработка BAR: значения `0` и `0xFFFFFFFF` считаются отсутствием BAR. Бит 0 означает порт ввода-вывода, биты 1–2 (`0x04`) — 64-битный BAR.
- Размер BAR: запись `0xFFFFFFFF` и инверсия маски с учётом выравнивания. Для портов маска обрезается по `0xFFFF`.

## Ограничения

- Механизм #1 (порты `0xCF8/0xCFC`) не работает с расширенным конфигурационным пространством PCIe (больше 256 байт). MMCONFIG/ECAM не поддерживается.
- Обход перечисляет все 256 шин каждый раз. На каждом вызове `pci_enumerate` выполняется до нескольких тысяч обращений к портам, поэтому частые вызовы заметно тормозят загрузку.
- Нет поддержки MSI и MSI-X: драйверы используют линии INTx или опрос.
- Нет мостов и ресурсов: драйвер не назначает адреса BAR, а только читает уже назначенные прошивкой.
- Записи в регистры команды и BAR не проверяют, идёт ли в этот момент DMA у устройства (например, при смене BAR во время работы).
