# Драйвер VBE (Bochs/QEMU DISPI, интерфейс `VBE_DISPI`)

Драйвер для эмулируемого видеоадаптера с интерфейсом Bochs VBE Dispi (`0xB0C0`–`0xB0C5`). Этот интерфейс отдаёт QEMU (`-vga std`), Bochs и часть совместимых эмуляторов. Драйвер умеет проверить наличие адаптера, узнать объём видеопамяти, найти framebuffer через PCI и переключить видеорежим через порты `0x1CE/0x1CF`.

Драйвер не участвует в загрузке видео: он вызывается из `src/userspace/display_mode.c` по запросу системного вызова смены режима, а при старте только логирует ID адаптера в `kernel.c`.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/display/vbe.h` | Публичный API |
| `src/drivers/display/vbe.c` | Реализация |

## Публичный API

| Функция | Что делает |
|---------|------------|
| `bool vbe_is_available(void)` | Пишет индекс ID `0xB0C5` и читает обратно. Адаптер есть, если значение в диапазоне `0xB0C0`–`0xB0C5` |
| `uint16_t vbe_debug_id(void)` | Возвращает сырое значение ID (для лога) |
| `uint64_t vbe_video_memory_bytes(void)` | Объём видеопамяти: регистр `VIDEOMEM` (в единицах 64 КБ) умножается на 65536. Возвращает 0, если адаптер не найден |
| `bool vbe_framebuffer_phys(uint64_t *out)` | Физический адрес framebuffer. Сначала ищется PCI-устройство класса `0x03` (дисплей) с BAR0 в памяти. Если не найдено, берётся физический адрес текущего GOP-буфера через `vmm_translate` |
| `bool vbe_set_mode(w, h, bpp, &aw, &ah)` | Переключает режим. Проверяет диапазоны, объём памяти, сравнивает запрошенные и фактически установленные параметры |
| `volatile void *vbe_map_framebuffer(phys, size)` | Отображает framebuffer через `mmio_map` (не более 16 МБ) |

### Ограничения параметров режима

- Ширина от 640 до 7680, высота от 400 до 4320.
- Глубина цвета 16, 24 или 32 бита.
- Размер кадра не больше объёма видеопамяти и не больше 16 МБ (`VBE_MAX_FRAMEBUFFER_BYTES`).

## Последовательность переключения режима

1. Проверка адаптера (`vbe_is_available`).
2. Проверка параметров и объёма памяти.
3. Отключение адаптера (`ENABLE = 0`), сброс банка.
4. Запись `XRES`, `YRES`, `BPP`, виртуального размера, смещений в ноль.
5. Включение с линейным framebuffer (`ENABLE = 0x01 | 0x40`).
6. Чтение обратно `XRES`, `YRES`, `BPP` и повторная проверка: адаптер может округлить размер или отказать.

## Где используется

- `src/userspace/display_mode.c:32, 114–133` — смена режима по запросу системного вызова (код компилируется в ядро). Порядок вызовов: `vbe_is_available`, `vbe_framebuffer_phys`, `vbe_set_mode`, `vbe_map_framebuffer`.
- `src/kernel/core/kernel.c:87-88` — лог `vbe_debug_id` при загрузке.
- `src/drivers/display/gop.c` и `svga.c` — конкурирующий путь. Если SVGA II активен, `gop_apply_live` переключает GOP на его framebuffer, и VBE-режим больше не нужен.

## Внутреннее устройство

- Регистры адресуются через пару портов `0x1CE` (индекс) и `0x1CF` (значение), обе операции 16-битные (`outw`/`inw`).
- Поиск framebuffer через PCI (`pci_enumerate`) использует класс `0x03`. Для BAR0 проверяется, что это память (бит 0 равен нулю), а не порт ввода-вывода.
- Физический адрес, найденный через GOP, выравнивается по 4 КБ (`& ~0xFFF`).

## Ограничения

- Работает только на эмуляторах с интерфейсом Bochs DISPI. На настоящем железе с Intel/AMD-видео драйвер не даст результата, там нужен отдельный драйвер (например, i915).
- Переключение режима делается без ожидания вертикальной синхронизации и без вызова BIOS. Это подходит для QEMU, но не гарантирует корректный результат на других адаптерах.
- Порты `0x1CE/0x1CF` доступны только из ядра. Пользовательская программа меняет режим через системный вызов, а не напрямую.
- Значение `VIDEOMEM` в единицах 64 КБ ограничивает объём: адаптер с 16 МБ даёт максимум 16 МБ.
