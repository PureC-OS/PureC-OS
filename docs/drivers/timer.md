# Драйвер таймера (PIT 8254 и TSC)

Драйвер отвечает за две вещи:

1. **Периодическое прерывание** от PIT (Programmable Interval Timer, канал 0) на IRQ0, которое запускает планировщик.
2. **Монотонный отсчёт времени и задержки** на основе TSC (Time Stamp Counter) с запасным вариантом, если TSC не откалиброван.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/interrupts/timer.h` | Объявления функций |
| `src/drivers/interrupts/timer.c` | Реализация |

## Публичный API

### `void timer_init(uint32_t frequency_hz)`

Настраивает PIT и разблокирует IRQ0 на PIC. Частота ограничивается диапазоном 100–2000 Гц. Делитель считается из базовой частоты PIT `1193182 Гц`, с округлением до ближайшего целого и ограничением `0xFFFF`. Реальная частота записывается в `timer_frequency_hz` и выводится в лог.

Также вызывается `detect_tsc_frequency()` и запоминается стартовое значение TSC.

Вызывается из `src/boot/boot.c:314` как `timer_init(1000)`.

### `void timer_tick(void)`

Увеличивает счётчик тиков `tick_count`. Вызывается из обработчика IRQ0 (вектор 32) в `src/arch/x86_64/idt/c/idt.c:190`, сразу перед `scheduler_on_timer_interrupt()`.

### `void timer_sleep(uint32_t milliseconds)`

Ожидание в миллисекундах. Поведение зависит от контекста:

- Если прерывания разрешены (`IF=1`), планировщик запущен и текущий поток не является idle, поток переводится в сон через `scheduler_sleep()`.
- Иначе (ранняя загрузка, idle-поток, прерывания запрещены) выполняется ожидание по TSC. Внутри цикла процессор уходит в `hlt` при разрешённых прерываниях или в `pause` при запрещённых. Время простоя накапливается в `idle_tsc`.

### `uint64_t timer_ticks(void)`

Возвращает время с момента `timer_init` в **миллисекундах** (по TSC). Несмотря на название, это не число тиков PIT. Сейчас именно эта функция используется всеми вызывающими модулями для измерения интервалов (`lapic.c`, `net_service.c`, `qemu_network_test.c`).

### `uint64_t timer_idle_tsc(void)`

Суммарное количество тактов TSC, проведённых в `hlt`/`pause` внутри `timer_sleep`. Нужно для оценки загрузки процессора.

## Определение частоты TSC

`detect_tsc_frequency()` использует CPUID:

1. Лист `0x15` (TSC/Core crystal clock): если заполнены `eax`, `ebx`, `ecx`, частота = `ecx * ebx / eax`.
2. Лист `0x16` (базовая частота процессора в МГц): частота = `eax * 1 000 000`.
3. Если ни один лист не дал значения, остаётся значение по умолчанию **3 ГГц**. На таком процессоре все задержки будут неточными.

## Внутреннее устройство

- `tsc_milliseconds()` переводит разницу TSC в миллисекунды, разбивая на секунды и остаток, чтобы не переполнить 64-битное произведение.
- `timer_frequency_hz` хранит реальную частоту PIT, `tsc_frequency_hz` — частоту TSC. Они независимы.
- `tick_count` инкрементируется в обработчике, но в текущем коде никто его не читает. Для времени используется TSC, а не счётчик тиков.

## Ограничения

- Имя `timer_ticks()` вводит в заблуждение: функция возвращает миллисекунды, а не тики. Если понадобится настоящий счётчик тиков, нужно будет читать `tick_count` через отдельную функцию.
- Точность `timer_ticks()` зависит от стабильности TSC. На процессорах без invariant TSC частота может плавать при смене состояний питания.
- PIT остаётся источником прерывания по времени для загрузочного процессора. В SMP-режиме таймер каждого ядра — LAPIC-таймер (вектор `SMP_TIMER_VECTOR`, `src/kernel/smp/lapic.c`). Его частота калибруется по `timer_ticks()` за 10 мс. Настройка LAPIC-таймера в этом драйвере не выполняется.
- Частота ограничена диапазоном 100–2000 Гц, передача значения вне него молча подменяется границей.
