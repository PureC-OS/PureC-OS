# Драйвер PIC 8259 (Programmable Interrupt Controller)

Драйвер каскадных контроллеров прерываний Intel 8259A (ведущий на портах `0x20/0x21`, ведомый на `0xA0/0xA1`). Используется для перепрограммирования векторов IRQ и маскирования всех линий до того, как прерывания будут переданы под управление APIC.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/interrupts/pic.h` | Объявления функций |
| `src/drivers/interrupts/pic.c` | Реализация |

## Публичный API

### `void pic_remap(uint8_t offset1, uint8_t offset2)`

Перепрограммирует оба контроллера (ICW1–ICW4). `offset1` задаёт базовый вектор для IRQ0–IRQ7 (ведущий), `offset2` — для IRQ8–IRQ15 (ведомый). В системе используется `pic_remap(0x20, 0x28)`, так как векторы `0x00–0x1F` заняты исключениями процессора.

Последовательность:

1. ICW1 = `0x11` (инициализация, ожидается ICW4) на оба контроллера.
2. ICW2 — базовые векторы.
3. ICW3 — ведущий: каскад на IRQ2 (`0x04`), ведомый: идентификатор каскада `0x02`.
4. ICW4 = `0x01` (режим 8086).

Между командами вызывается `io_wait()`, которая пишет в порт `0x80` (POST-порт), давая контроллеру время обработать команду.

### `void pic_mask_all(void)`

Записывает `0xFF` в регистры маски обоих контроллеров — все IRQ замаскированы. Вызывается сразу после `pic_remap`, чтобы ни одно внешнее прерывание не пришло до того, как обработчики будут готовы.

## Где вызывается

- `src/boot/boot.c:297` — основной путь загрузки: `pic_remap(0x20,0x28); pic_mask_all();`
- `src/boot/grub_main.c:50-51` — путь через Multiboot2 (GRUB) делает то же самое.

Отдельно разблокировкой линий занимаются вызывающие драйверы: например, `timer_init` снимает маску с IRQ0 (см. [timer.md](timer.md)).

## Ограничения

- Драйвер не знает о LAPIC и I/O APIC. Для этих контроллеров в ядре есть отдельный код (`src/kernel/smp/lapic.c`, `lapic_eoi`). Взаимодействие PIC и APIC драйвер не описывает и не настраивает. В `boot.c` `timer_init` вызывается после `pic_mask_all`, поэтому IRQ0 снова разблокируется на PIC.
- Функция конца прерывания для PIC (`pic_eoi`) не входит в драйвер. Она объявлена `static` в обработчике IDT (`src/arch/x86_64/idt/c/idt.c:60`).
- Маска читается и пишется целиком. Точечного включения или выключения одной линии в драйвере нет; `timer_init` сам читает маску и сбрасывает бит 0.
