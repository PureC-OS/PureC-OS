# Драйвер последовательного порта (COM1, UART 16550)

Минимальный драйвер вывода в последовательный порт COM1 (`0x3F8`). Используется как канал отладки: лог загрузки, сообщения ядра и тестов уходят в `serial_write_string`. Драйвер только передаёт данные, приём не реализован.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/serial/serial.h` | Объявления функций |
| `src/drivers/serial/serial.c` | Реализация |

## Публичный API

### `void serial_init(void)`

Настраивает UART:

| Регистр (смещение) | Значение | Смысл |
|--------------------|----------|-------|
| IER (`+1`) | `0x00` | Прерывания выключены |
| LCR (`+3`) с DLAB | `0x80` | Открывается доступ к делителю |
| DLL (`+0`) | `0x03` | Делитель 3 → 38400 бод (при базе 115200) |
| DLM (`+1`) | `0x00` | Старший байт делителя |
| LCR (`+3`) | `0x03` | 8 бит данных, 1 стоп-бит, без чётности, DLAB сброшен |
| FCR (`+2`) | `0xC7` | FIFO включён и очищен, порог 14 байт |
| MCR (`+4`) | `0x0B` | DTR, RTS и OUT2 |

Скорость 38400 бод является следствием делителя 3 при базовой частоте 115200. Для лога на реальной машине этого достаточно, но при желании скорость можно повысить, уменьшив делитель.

### `void serial_putc(char c)`

Ждёт, пока в регистре LSR (`+5`) не освободится передатчик (бит `0x20`), и пишет байт. Если символ — `'\n'`, дополнительно отправляется `'\r'`, чтобы терминал на другом конце правильно переводил строку.

### `void serial_write_string(const char *s)`

Выводит нуль-терминированную строку через `serial_putc`.

## Где используется

- `src/boot/boot.c:219` и `src/boot/grub_main.c:28` — инициализация в начале загрузки.
- `src/kernel/syscall/syscall.c` — вывод неизвестных системных вызовов и адресов.
- `src/arch/x86_64/idt/c/idt.c` — сообщения об обработке `#BP`.
- Пути `[GOP]`, `[PIC]`, `[INT]`, `[TEST]` в загрузочном коде.

## Ограничения

- Жёстко задан COM1 (`0x3F8`). Выбрать другой порт нельзя, и обнаружения через ACPI/PCI нет.
- Вывод **блокирующий**: без таймаута, если UART не отвечает (например, порт не подключён, а LSR не выставляет бит пустого передатчика), `serial_putc` зависает в цикле.
- Приёма данных нет. Ввод с последовательного порта не поддерживается.
- Драйвер не синхронизирован: одновременный вызов с нескольких ядер (SMP) может перемешать вывод.
- Для проверки на реальном железе нужен переходник USB–UART или QEMU с `-serial stdio`.
