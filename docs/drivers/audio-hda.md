# Драйвер Intel HDA (High Definition Audio)

Драйвер контроллера Intel HDA (класс PCI `04:03`) и кодека на шине. Контроллер принимает команды через кольцо CORB и отвечает через RIRB. Драйвер обходит граф виджетов кодека, находит путь от выходного DAC до пина динамика или наушников, настраивает его и запускает DMA-поток. Верхний слой (громкость, выбор выхода, PCM-очередь) описан в [audio.md](audio.md).

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/audio/audio_hda.h` | Публичный API и структуры `hda_controller_info`, `hda_output_device_info` |
| `src/drivers/audio/audio_hda.c` | Реализация (около 1400 строк) |

## Публичный API

| Функция | Что делает |
|---------|------------|
| `hda_init()` | Перечисляет PCI-устройства класса HDA, инициализирует контроллер и кодеки, выбирает выход |
| `hda_set_address_mapping(phys, virt)` | Передаёт базы для перевода виртуальных адресов в физические. Нужно для DMA-буферов |
| `hda_is_present()` | Контроллер найден и отображён |
| `hda_pcm_output_ready()` | PCM-выход настроен и доступен |
| `hda_output_device_count()`, `hda_selected_output_device()` | Количество найденных выходов и текущий выбор |
| `hda_get_output_device(index, out)` | Сведения о выходе: адрес кодека, узлы DAC и пина, маршрут |
| `hda_select_output_device(index)` | Переключает выход (останавливает поток, перенастраивает маршрут) |
| `hda_set_master_volume(vol, muted)` | Громкость на усилителях маршрута |
| `hda_play_tone(freq_hz, vol)` | Заполняет DMA-буфер меандром нужной частоты и запускает поток |
| `hda_stop_tone()` | Останавливает поток |
| `hda_pcm_fill_half(half, frames, count)` | Копирует полубуфер PCM (до 4096 стерео-кадров) и дополняет нулями |
| `hda_pcm_start()`, `hda_pcm_stop()` | Запускает и останавливает поток PCM |
| `hda_pcm_position()` | Значение LPIB (байтовая позиция в кольцевом буфере) |
| `hda_get_controller_info(out)` | Сведения о контроллере: версия, число потоков, ID устройства |

## Параметры потока

- Формат `0x4011`: 44,1 кГц, 16 бит, 2 канала.
- DMA-буфер: два полубуфера по 16 КБ (4096 стерео-кадров), итого 32 КБ. Список BDL из двух записей, LVI = 1, CBL = 32768.
- Тег потока `HDA_STREAM_TAG = 1`, канал 0.
- Дескриптор выходного потока находится после входных: смещение `0x80 + input_streams * 0x20`.

## Инициализация

1. `inspect_audio_device` (через `pci_enumerate`) ищет первое устройство класса `04:03`. Включает bus master и доступ к памяти (`command | 0x06`).
2. Читает BAR0, отображает регистры через `mmio_map` (размер `0x4000`). Считывает число входных, выходных и двунаправленных потоков из регистра `GCAP`.
3. `setup_pcm` сбрасывает контроллер (`reset_controller`), настраивает CORB и RIRB (`setup_command_ring`), проверяет `STATESTS`.
4. Для каждого адреса кодека из `STATESTS` вызывается `discover_codec`. Ищется группа функций аудио (`find_audio_function_group`), затем пересчитываются виджеты.
5. Для каждого найденного выхода вызывается `configure_output_device`. Первый удачный становится выбранным.

## Обход графа (`discover_codec`)

- Для каждого виджета читаются возможности (`WIDGET_CAPS`), тип и число соединений.
- Выходные DAC и пины собираются в таблицу (`register_output_device`), если пин поддерживает выход (`PIN_CAP_OUTPUT`).
- Маршрут от пина до DAC строится через `discover_routes_from_node` (до 16 узлов, `HDA_MAX_ROUTE_NODES`). Соединения читаются через `GET_CONNECTION_LIST_ENTRY`.

## Настройка выхода (`configure_codec`)

Для выбранного выхода:

1. Группа функций и DAC переводятся в состояние D0 (`set_widget_power_d0`).
2. Для каждого узла маршрута, от пина к DAC, выставляется соединение (`SET_CONNECTION_SELECT`, если их больше одного), затем разблокируется усилитель (`unmute_route_widget`). Усиление берётся как 0 дБ (`amp_zero_db_gain`) или по запросу громкости (`amp_gain_for_volume`).
3. Пин включается (`PIN_WIDGET_CONTROL = 0x40`, выход). Если поддерживается EAPD, он включается (`EAPD_BTL = 0x02`).
4. DAC привязывается к потоку (`CONVERTER_STREAM_CHANNEL`) и получает формат (`STREAM_FORMAT`).

Переключение выхода сначала отключает текущий (`deactivate_current_output`), затем настраивает новый.

## Тоны и PCM

- `hda_play_tone` заполняет оба полубуфера квадратной волной. Амплитуда = `32767 * volume / 100`. Частота фазы считается в целых числах по 44,1 кГц.
- `hda_pcm_fill_half` копирует данные из буфера вызывающего кода и дополняет хвост полубуфера нулями. Данные из `audio.c` поступают через `pcm_scratch`.
- Запуск и остановка потока идут через бит `RUN` регистра управления потоком (`HDA_STREAM_RUN = 0x02`). Ожидание подтверждения выполняется `wait_stream_control` с ограничением `HDA_TIMEOUT` (1 000 000 итераций).

## Ограничения

- Прерывания не настроены. Позиция проигрывания опрашивается через LPIB из `audio_update`. Так сделано намеренно, пока нет обработчика IRQ для потока.
- Поддерживается только один поток вывода (индекс потока `input_streams`). Входной звук (микрофон) не реализован.
- Нет поддержки сжатых форматов и 24-битного звука. Формат жёстко задан `0x4011`.
- Нет обработки jack-событий (вставка и извлечение наушников). Выбор выхода делается вручную через `audio_select_output_device`.
- Ожидания (сброс, CORB/RIRB, RUN потока) ограничены `HDA_TIMEOUT` = 1 000 000 итераций опроса, а не временем. Зависший контроллер задержит загрузку на заметное время.
- Статус проверки: в проекте нет записей о том, что звук через HDA проверен на железе или в эмуляторе. Считать рабочим нельзя, пока это не проверено.
