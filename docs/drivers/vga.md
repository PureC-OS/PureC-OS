# Драйвер VGA текстового режима

Вывод в текстовый буфер VGA 80×25 по адресу `0xB8000` (символ + атрибут, два байта на ячейку). Это самый простой путь вывода, который работает даже без графического режима. Используется как запасной вариант, когда ни GOP, ни framebuffer не доступны.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/display/vga.h` | Объявления функций |
| `src/drivers/display/vga.c` | Реализация |

## Публичный API

| Функция | Что делает |
|---------|------------|
| `void vga_init(void)` | Очищает экран (`vga_clear`) |
| `void vga_set_hhdm(uint64_t offset)` | Задаёт смещение HHDM (higher-half direct map). Адрес буфера становится `offset + 0xB8000`. При `offset == 0` используется физический адрес |
| `void vga_clear(void)` | Заполняет экран пробелами с атрибутом `0x0F` (белый на чёрном), курсор в `(0, 0)` |
| `void vga_putc(char c)` | Выводит символ. Поддерживаются `\n` и `\r` |
| `void vga_write(const char *s)` | Выводит строку через `vga_putc` |

## Где используется

- `src/boot/boot.c:249-251` — `vga_set_hhdm` вызывается с HHDM-смещением Limine (или с 0, если его нет).
- `src/boot/grub_main.c:26` — `vga_init` в пути Multiboot2 (GRUB).
- `src/drivers/display/gop.c` — `gop_putc` переходит на `vga_putc`, пока GOP не доступен.

## Внутреннее устройство

- Курсор хранится в статических `cur_x`, `cur_y` (`uint8_t`).
- Прокрутка (`scroll`) копирует строки 1–24 на место 0–23 и очищает последнюю строку. Вызывается при выходе курсора за 25-ю строку.
- Перенос строки при достижении 80 столбца выполняется автоматически.

## Ограничения

- Курсор аппаратно не двигается: это только программный курсор, аппаратный курсор (порты `0x3D4/0x3D5`) не обновляется.
- Цвет фиксирован (`COLOR = 0x0F`), изменить его из API нельзя.
- Драйвер не синхронизирован. Вызов с нескольких ядер может перемешать вывод.
- Экран 80×25 фиксирован. На современных машинах в UEFI-режиме текстового буфера обычно нет, поэтому драйвер используется в основном для отладки BIOS/GRUB-пути.
