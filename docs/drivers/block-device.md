# Блочный слой хранения (`block_device`)

`src/drivers/storage/block_device.c` объединяет все накопители системы в одну таблицу и даёт остальному ядру один интерфейс чтения и записи 512-байтных секторов. Под ним работают четыре транспорта: ATA PIO, AHCI, xHCI (USB Mass Storage) и EHCI (USB Mass Storage). Блочный слой выбирает активный накопитель, перенаправляет операции на нужный драйвер, следит за USB-накопителями при подключении и отключении.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/storage/block_device.h` | Публичный API |
| `src/drivers/storage/block_device.c` | Таблица устройств, выбор активного, перенаправление, hotplug |
| `src/drivers/storage/storage_types.h` | Структуры `storage_device_info`, `storage_controller_info`, коды транспортов |

## Таблица устройств

Индексы накопителей идут подряд по транспортам в фиксированном порядке:

1. ATA PIO (`ata_pio_device_count()`)
2. AHCI (`ahci_device_count()`)
3. xHCI (`xhci_device_count()`)
4. EHCI (`ehci_device_count()`)

`block_device_get_info(index, info)` находит нужный транспорт по этому порядку, вычитая количества предыдущих. Поле `selected` в результате показывает активный накопитель.

Имена вида `/dev/sdX` выдаёт каждый драйвер сам, а буква вычисляется от `linux_name_base`, то есть от числа уже найденных накопителей.

## Инициализация (`block_device_init`)

Выполняется один раз, при первом обращении к любой функции слоя:

1. `ata_pio_init()`, `ahci_init(...)`, `xhci_init(...)`, `ehci_init(...)` — каждый получает базу имён, равную количеству накопителей предыдущих транспортов.
2. Активный транспорт выбирается по приоритету: ATA PIO, затем AHCI, затем xHCI, затем EHCI. Выбирается первый накопитель этого транспорта (индекс 0).
3. Результатом считается `true`, если хотя бы один транспорт нашёл накопитель.

## Публичный API

| Функция | Что делает |
|---------|------------|
| `block_device_init()` | Инициализация, см. выше |
| `block_device_is_ready()` | Инициализация завершена |
| `block_device_count()`, `block_device_list(devices, cap)`, `block_device_get_info(i, info)` | Список накопителей |
| `block_device_find(name)` | Индекс по имени `/dev/sdX`, `-1` если нет |
| `block_device_select(index)` | Выбор активного накопителя. Для USB запоминается серийный номер |
| `block_device_read(lba, buf)`, `block_device_write(lba, buf)` | Один сектор |
| `block_device_read_sectors(lba, buf, n)`, `block_device_write_sectors(lba, buf, n)` | Несколько секторов |
| `block_device_flush()` | Сброс кэша записи активного накопителя |
| `block_device_name()` | Имя активного накопителя |
| `block_device_rescan_usb()` | Повторное сканирование xHCI и EHCI, восстановление выбора |
| `block_device_poll_usb_hotplug()` | Проверка изменения топологии USB не чаще раза в секунду |
| `block_device_begin_exclusive_io()`, `block_device_end_exclusive_io()` | Блокировка сканирования USB на время длительной операции |

## Работа с USB-накопителями

- **Пакетная передача.** USB-операции идут через общий буфер `usb_bounce` размером 32 сектора (16 КБ). Длинный запрос режется на куски по 32 сектора (`usb_read_run`, `usb_write_run`).
- **Блокировка сканирования.** Перед операцией берётся `usb_rescan_lock` (спин-подобная блокировка с `scheduler_sleep(1)`). Сканирование и чтение не выполняются одновременно.
- **Восстановление выбора.** При `block_device_select` серийный номер USB-накопителя запоминается. После пересканирования блочный слой ищет накопитель с тем же серийным номером и снова делает его активным. Так выбор не сбрасывается, когда флешка переехала на другой порт или индекс изменился.
- **Hotplug.** `block_device_poll_usb_hotplug` вызывается из цикла, проверяет `xhci_topology_changed()` и `ehci_topology_changed()`, при изменении запускает `block_device_rescan_usb()`.

## Где используется

- `src/fs/ext2/` (`block.c`, `ext2.c`, `super.c`, `format.c`, `debug.c`) — чтение и запись секторов EXT2.
- `src/fs/vfs.c`, `src/fs/devfs.c`, `src/fs/procfs.c`, `src/fs/sysfs.c` — выбор и информация о накопителях.
- `src/fs/install.c` — запись на накопитель при установке системы.
- `src/kernel/syscall/syscall.c` — системные вызовы информации о накопителях и выбора.
- `src/drivers/storage/storage_probe.c` блочный слой не вызывает: он только перечисляет контроллеры.

## Ограничения

- Активен только один накопитель. Блочный слой не умеет адресовать два диска сразу: все операции идут на выбранное устройство. Для работы с другим диском его нужно выбрать заново.
- Приоритет транспортов задаётся при инициализации. Если есть ATA-диск, USB-накопитель, подключённый позже, не станет активным автоматически, его нужно выбрать явно.
- Нет кэша секторов. Каждый вызов идёт прямо в драйвер.
- Блокировка USB-пути ждёт через `scheduler_sleep(1)`. Поэтому вызывать её до запуска планировщика нельзя. Проверки этого сценария в коде нет.
- Hotplug опрашивается, а не приходит по прерыванию, с задержкой до секунды.
