# Драйвер VMware SVGA II

Драйвер виртуального видеоадаптера VMware SVGA II (PCI `15AD:0405`). Его отдают QEMU с `-vga vmware`, VirtualBox в режиме VMSVGA и VMware. Адаптер работает через регистры ввода-вывода и FIFO команд в памяти. Драйвер нужен, чтобы ускорить вывод: вместо записи в framebuffer можно послать команду `UPDATE` с прямоугольником, а хост перерисует окно сам. Если адаптер недоступен, всё работает через GOP без ускорения.

## Публичный API

| Функция | Что делает |
|---------|------------|
| `bool svga_probe_only(void)` | Только ищет устройство по PCI, ничего не инициализирует |
| `bool svga_init(w, h, bpp)` | Полная инициализация, см. ниже. По умолчанию 1024×768×32 |
| `bool svga_is_available(void)` | Устройство инициализировано и готово (`g.ready`) |
| `void *svga_fb_virt(void)` | Виртуальный адрес framebuffer (с учётом смещения `FB_OFFSET`) |
| `svga_width`, `svga_height`, `svga_pitch_pixels`, `svga_bpp`, `svga_fb_size` | Параметры текущего режима |
| `uint32_t svga_caps(void)` | Битовая маска возможностей (`RECT_FILL` = бит 0, `RECT_COPY` = бит 1) |
| `void svga_update(x, y, w, h)` | Команда `UPDATE`: сообщить хосту, что прямоугольник изменился |
| `bool svga_fill(color, x, y, w, h)` | Команда `RECT_FILL`, если поддерживается |
| `bool svga_copy(sx, sy, dx, dy, w, h)` | Команда `RECT_COPY`, если поддерживается |
| `void svga_sync(void)` | Ждёт, пока хост закончит обработку FIFO (`SYNC` + `BUSY`) |
| `const char *svga_status_line(void)` | Строка состояния для лога (`svga: ok fb=…x… caps=…`) |
| `svga_collect_io_ranges(...)` | Сбор занятых диапазонов портов по всем PCI-устройствам (для переноса IO-базы) |

## Инициализация (`svga_init`)

1. Поиск устройства `15AD:0405` через `pci_enumerate`.
2. Включение доступа: I/O, память и bus master через `pci_update_command`.
3. Чтение BAR0 — базы регистров ввода-вывода (выравнивается по 4 байтам).
4. Самопроверка: чтение `0xCF8/0xCFC` и сравнение с конфигурацией, лог `IO_OK` или `IO_BROKEN`.
5. Подбор версии протокола: `svga_try_ids` пишет `0x90000002` и читает обратно. Если не совпало, пробует `0x90000001` и `0x90000000`. Если ничего не подошло, IO-база переносится на свободный адрес (поиск с `0x5000` шагом размера BAR) и подбор повторяется.
6. Установка режима: `ENABLE=0`, затем `WIDTH`, `HEIGHT`, `BPP`, `ENABLE=1`. Результат читается обратно. Требуется 32 бита на пиксель, `bytes_per_line == width * 4`, размеры от 64 до 7680×4320.
7. Чтение `FB_SIZE`, `MEM_SIZE` (объём FIFO), BAR1 (framebuffer), BAR2 (FIFO).
8. Отображение обоих BAR через `mmio_map`. Framebuffer смещается на `FB_OFFSET`.
9. Инициализация FIFO: `MIN` = число регистров × 4, `MAX` = размер FIFO, `NEXT_CMD` и `STOP` = `MIN`. Затем `CONFIG_DONE = 1`.
10. `g.ready = true`, лог `svga: WxHx32 io=… fb=… fifo=… caps=… id=…`.

На любом шаге при ошибке драйвер возвращает `false`, пишет причину в `g_status` и в лог, и ядро переходит на GOP.

## Записи в FIFO

- `fifo_write_word` проверяет свободное место в кольцевом буфере (`max - min`). Если места мало, до миллиона раз вызывает `SYNC` и ждёт `BUSY = 0`.
- Команда пишется как последовательность 32-битных слов: идентификатор команды, затем аргументы. Указатель `NEXT_CMD` сдвигается с переносом по кольцу.
- Команды: `UPDATE` (1, 4 аргумента), `RECT_FILL` (2, 5 аргументов), `RECT_COPY` (3, 6 аргументов).

Координаты обрезаются по размеру экрана, пустые прямоугольники отбрасываются.

## Где используется

- `src/kernel/core/kernel.c:93-95` — при `pref != 1` (не задан `video=gop`/`nogpu`/`video=safe`) вызывается `svga_init(1024, 768, 32)`, затем `gop_apply_live` переводит GOP на framebuffer SVGA.
- `src/drivers/display/gop.c` — после записи в backbuffer вызывает `svga_update` для 32-битного пути.
- `src/gfx/compositor.c:602` — композитор сообщает о грязной области через `svga_update`.
- `src/boot/boot.c:109-112` — параметры загрузки `video=gop` / `nogpu` / `video=safe` запрещают SVGA, `video=svga` / `video=gpu` требуют его.

## Ограничения

- Работает только с 32-битным режимом. Другие глубины цвета отвергаются.
- `svga_fill`, `svga_copy`, `svga_sync`, `svga_caps`, `svga_fb_size` и `svga_probe_only` нигде не вызываются вне `svga.c`. Вся отрисовка идёт через backbuffer GOP и команду `UPDATE`, команды `RECT_FILL` и `RECT_COPY` не отправляются.
- Ожидание FIFO (`fifo_write_word`) использует цикл до 1 000 000 итераций без таймаута по времени. Если хост завис, ядро будет висеть в этом цикле.
- `svga_sync` тоже ограничен по числу итераций, а не по времени. Возврат из функции не говорит о завершении работы хоста.
- Сбой при переносе IO-базы восстанавливает оригинальный BAR, но часть регистров PCI может остаться в промежуточном состоянии.
- Проверено только в эмуляторах (QEMU, VirtualBox). Адаптер VMware SVGA II — виртуальный, на реальном железе его ожидать не стоит.
