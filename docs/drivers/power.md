# Драйвер питания (обёртка над ACPI)

`src/drivers/power` — тонкий слой между ядром и подсистемой ACPI. Сама реализация ACPI лежит в отдельном модуле `acpi/` (подключён как сабмодуль). Драйвер передаёт ACPI адрес RSDP и смещение HHDM, а затем предоставляет четыре операции: перезагрузка, выключение, данные о батарее и тепловые датчики.

Все операции через ACPI выполняются только если инициализация прошла. Если ACPI недоступен, перезагрузка и выключение идут по запасным путям самого модуля ACPI.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/power/power.h` | Публичный API |
| `src/drivers/power/power.c` | Обёртка, заполнение `struct battery_info` и `struct thermal_info` |
| `acpi/include/acpi/acpi.h` | API модуля ACPI (внешний сабмодуль) |
| `acpi/src/*.c` | Реализация: таблицы, S5, батарея, EC, датчики, uACPI-клей |

Структуры `battery_info` и `thermal_info` объявлены в `src/kernel/syscall/syscall.h`, их читают системные вызовы.

## Публичный API

| Функция | Что делает |
|---------|------------|
| `void power_init(void)` | Вызывает `acpi_init(rsdp, hhdm)`. При успехе выводит таблицы через `acpi_dump_tables()`. При ошибке пишет предупреждение в лог |
| `void power_reboot(void)` | `acpi_reboot()`, затем бесконечный `cli; hlt`, если перезагрузка не произошла |
| `void power_shutdown(void)` | `acpi_shutdown()`, затем бесконечный `cli; hlt` |
| `bool power_battery_get(struct battery_info *out)` | Заполняет данные о батарее |
| `bool power_thermal_get(struct thermal_info *out)` | Заполняет данные о температуре и вентиляторах |

## Данные о батарее

`power_battery_get` всегда возвращает `true`, если указатель не нулевой. Поля:

- `present`: 1, если ACPI нашёл батарею.
- `name`: `BAT0`, `BAT1` и т. д. или имя из ACPI. Если есть имя модели, оно дописывается через пробел.
- `percent`, `charging`, `voltage_mv`, `current_ma`, `remaining_minutes`: берутся из `acpi_battery_refresh`, если он вернул действительные данные.
- `status_text`: `OK`, `Charging`, `Full` (от 99%), `Discharging`, `No battery`, `Not present (_STA)`, `Unknown (...)`. Строка `Unknown` объясняет причину: нет `_BIF`/`_BST`, нет AML или не удалось выполнить метод.

Если значение процента не получено, поле `percent` равно `BATTERY_PERCENT_UNKNOWN`.

## Данные о температуре

`power_thermal_get` возвращает `false`, если `acpi_thermal_get` не дал результата. Иначе заполняются:

- `available`, `thermal_zone_count`, `fan_count`
- `temperature_deci_c` (в десятых долях градуса, при отсутствии датчика `0x80000000`)
- `fan_rpm`, `thermal_zone` и `fan` (имена зон и вентиляторов)

## Где используется

- `src/kernel/core/kernel.c:69` — `power_init()` при старте ядра.
- `src/kernel/syscall/syscall.c:809-824` — системные вызовы выключения, перезагрузки, батареи и температуры.

## Модуль ACPI (внешний сабмодуль `acpi/`)

Кратко, что делает модуль, по файлам:

- `acpi.c` — поиск RSDP, разбор XSDT/RSDT с проверкой контрольных сумм, FADT, включение режима ACPI (`SCI_EN`), разбор MADT (LAPIC, I/O APIC).
- `acpi_s5.c` — извлечение типов сна S5 из DSDT для выключения.
- `acpi_power.c` — последовательности выключения и перезагрузки.
- `acpi_battery.c` — поиск батарей `BAT0`–`BAT3` и `PNP0C0A`, адаптера `ACPI0003`, вычисление состояния через `_BIF`/`_BIX`/`_BST`.
- `acpi_ec.c` — контроллер embedded controller (EC), установка обработчиков после полной инициализации uACPI.
- `acpi_sensors.c` — тепловые зоны и вентиляторы.
- `uacpi_glue.c`, `uacpi_heap.c` — клей между ядром и библиотекой uACPI.

Многие операции (батарея, EC, датчики) требуют, чтобы uACPI был полностью инициализирован. Проверка делается через `acpi_uacpi_full_ready()`. Пока её нет, эти функции возвращают «неизвестно» или откладывают установку.

## Ограничения

- Значения батареи и температуры зависят от AML-методов прошивки. На машинах, где эти методы сломаны, драйвер вернёт `Unknown`, а не значение.
- Выключение и перезагрузка не гарантированы: если ACPI-путь не сработал, функции переходят к `cli; hlt`, и система просто останавливается.
- Драйвер не обрабатывает события ACPI (кнопка питания, крышка ноутбука, SCI). Они не отслеживаются.
- Описание модуля в `acpi/README.md` устарело: в нём сказано, что AML-исполнителя нет, но в коде уже используется uACPI. Ориентироваться стоит на исходники.
- Чтение батареи и температуры на реальном железе (i5-1235U) в списке открытых задач. Считать их проверенными нельзя.
