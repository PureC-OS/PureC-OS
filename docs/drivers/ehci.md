# Драйвер контроллера USB EHCI (USB 2.0)

Драйвер контроллера EHCI (класс PCI `0C/03/20`). Работает с устройствами USB 2.0 (high-speed) и умеет только одно: найти накопитель класса Mass Storage с протоколом Bulk-Only и дать к нему блочный доступ. Мыши и клавиатуры через EHCI не поддерживаются, хабы не перечисляются.

Основная работа с USB на машинах с xHCI идёт через [xHCI](xhci.md). EHCI нужен для старых контроллеров и для накопителей, которые подключены через USB 2.0-порты контроллера, не отданного xHCI.

## Расположение

| Файл | Назначение |

## Публичный API

API полностью повторяет интерфейс xHCI, поэтому блочный слой выбирает драйвер одинаково:

| Функция | Что делает |
|---------|------------|
| `ehci_set_address_mapping(hhdm, phys, virt)` | Базы для DMA |
| `ehci_init(linux_name_base)` | Однократная инициализация контроллера и портов |
| `ehci_rescan(linux_name_base)` | Повторное перечисление портов |
| `ehci_topology_changed()` | Есть ли изменения на портах |
| `ehci_device_count()`, `ehci_get_device_info`, `ehci_select_device` | Список накопителей и выбор |
| `ehci_read_sector(s)`, `ehci_write_sector(s)`, `ehci_flush_cache` | Блочный ввод-вывод по 512 байт |
| `ehci_device_name()` | Имя текущего накопителя |
| `ehci_get_probe_stats(stats)` | Счётчики: контроллеры, подключённые порты, high-speed порты, накопители, ошибки, последний этап |

- `src/drivers/storage/block_device.c:182` — `ehci_rescan` при повторном сканировании.

## Инициализация (`initialize_controller`)

1. Включаются bus master и доступ к памяти, отображаются регистры (`mmio_map`).
2. `take_ownership` ищет в PCI-конфигурации capability `USBLEGSUP` (ID 1) по смещению `HCCPARAMS >> 8`. Ставит бит запроса у OS и ждёт, пока BIOS отпустит контроллер (`EHCI_TIMEOUT` = 50 000 000 итераций). Затем обнуляет регистр управления (`USBLEGCTLSTS`).
3. Контроллер останавливается, сбрасывается, включается асинхронный список (`EHCI_CMD_ASYNC`). Каждый шаг ждёт подтверждения в `USBSTS`.
4. Порты: питание включается, на каждом проверяется `PORTSC`. Если порт отдан компаньонскому контроллеру (бит `OWNER` = 1), он принадлежит OHCI или UHCI, и EHCI его не трогает. Иначе порт сбрасывается, и если он стал high-speed, он учитывается в `high_speed_ports`.

## Перечисление (`enumerate_port`)

1. Устройство получает адрес `индекс + 1`. Первый запрос идёт на адрес 0, дескриптор устройства читается по 8 байт, чтобы узнать размер максимального пакета.
2. `SET_ADDRESS` на новый адрес, затем полный дескриптор устройства (18 байт) и конфигурации.
3. `parse_mass_storage` ищет интерфейс `08` / `06` / `50` с парой bulk-endpoint'ов. Если его нет, вызывается `detect_hid_mouse`, который только пишет в лог, что мышь на EHCI не поддерживается.
4. `SET_CONFIGURATION`, затем `identify_device`: до трёх попыток `TEST UNIT READY`, затем `INQUIRY` и `READ CAPACITY(10)`. Формируются имя (`/dev/sdX`), серийный номер и модель.

Устройств на контроллер не больше четырёх (`EHCI_DEVICE_LIMIT`).

## Передача данных

- Управляющие передачи (`control_transfer`) и bulk-передачи (`bulk_transfer`) строятся как цепочки qTD, привязанные к queue head в асинхронном списке.
- Каждая очередь ставится в список (`execute_schedule`), после чего ждётся завершение: бит `ACTIVE` сбрасывается, ошибки проверяются по маске `EHCI_QTD_ERRORS`.
- Команды Bulk-Only (`bulk_only_command`) следуют тому же протоколу, что и в xHCI: CBW, данные, CSW.
- Буферы, пересекающие границу DMA-сегмента 4 КБ, разбиваются (`same_dma_segment`, `set_qtd_buffer`).

## Ограничения

- Только асинхронный список. Периодический список для прерываний не используется, поэтому мыши и клавиатуры не работают.
- Хабы не перечисляются. Наличие хаба в логе отмечается, но дочерние порты недоступны.
- Нет прерываний: завершение передач проверяется опросом, а ожидания ограничены `EHCI_TIMEOUT`.
- Устройства только Bulk-Only; протоколы UAS и другие классы не поддерживаются.
- Ограничение на четыре устройства (`EHCI_DEVICE_LIMIT`): порты сверх этого числа при сканировании не обрабатываются.
- В проекте нет зафиксированных результатов проверки на конкретном железе. При проблеме смотрите `ehci_get_probe_stats` и лог строк `ehci%u: port%u`.
