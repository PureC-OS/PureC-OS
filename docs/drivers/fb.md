# Драйвер framebuffer (`fb`) — устаревший путь вывода Limine

Простой текстовый вывод поверх линейного framebuffer, который передаёт загрузчик Limine. Драйвер рисует символы шрифтом `GFX_FONT_CLASSIC` через `gfx/text`, держит курсор и умеет прокручивать экран.

> **Статус: не используется.** В дереве нет вызовов `fb_init`, `fb_putc`, `fb_clear`, `fb_write_string` или `fb_write_hex` вне самого файла. Загрузочный путь пишет в framebuffer через `gop` (см. [gop.md](gop.md)), который делает то же самое, но умеет консоль на пользователя, двойную буферизацию и прокрутку через backbuffer. Драйвер сохранён как минимальная реализация для возможного восстановления, его можно удалить, если он не понадобится.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/display/fb.h` | Объявления функций |
| `src/drivers/display/fb.c` | Реализация |

## Публичный API

| Функция | Что делает |
|---------|------------|
| `void fb_init(struct limine_framebuffer *fb)` | Запоминает адрес, размеры и pitch (в пикселях) из структуры Limine. Курсор ставится в `(12, 12)` |
| `void fb_clear(uint32_t color)` | Заполняет весь экран цветом и возвращает курсор в `(12, 12)` |
| `void fb_set_color(uint32_t fg, uint32_t bg)` | Меняет цвет текста и фона |
| `void fb_putc(char c)` | Выводит символ. Поддерживаются `\n` и `\r` |
| `void fb_write_string(const char *s)` | Выводит строку |
| `void fb_write_hex(uint64_t v)` | Выводит 16 шестнадцатеричных цифр с префиксом `0x` |

Шаг символа — 8 пикселей по горизонтали, 10 по вертикали. Поля слева и сверху — 12 пикселей.

## Внутреннее устройство

- `fb_scroll` сдвигает весь экран на 10 строк через `memcpy`, затирает освободившуюся часть фоновым цветом.
- Текст рисуется напрямую в framebuffer, без промежуточного буфера. Каждый символ отдельно через `gfx_draw_text_opaque`.
- Pitch хранится в пикселях (`fb->pitch / 4`), что верно только для 32-битного режима.

## Ограничения

- Работает только с 32 битами на пиксель. Для 16 и 24 бит пиксели записываются неверно.
- Нет двойной буферизации: каждый символ сразу меняет видимый экран, что даёт мерцание при частом выводе.
- Нет синхронизации, вызов с нескольких ядер может испортить вывод.
- Ширина и высота берутся один раз в `fb_init` и не обновляются при смене режима.
