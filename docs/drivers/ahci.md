# Драйвер AHCI (SATA)

Драйвер контроллера SATA в режиме AHCI (класс PCI `01/06/01`). Находит подключённые SATA-диски, читает IDENTIFY, а затем выполняет чтение и запись секторов командами DMA. Работает опросом: прерывания портов выключены, и драйвер ждёт завершения команды в цикле.

## Расположение

| Файл | Назначение |
|------|------------|
| `src/drivers/storage/ahci.h` | Публичный API и `struct ahci_probe_stats` |
| `src/drivers/storage/ahci.c` | Реализация (около 475 строк) |

Контроллер выбирает `storage_probe` (см. [storage-probe.md](storage-probe.md)). Накопители попадают в общую таблицу через [блочный слой](block-device.md).

## Публичный API

| Функция | Что делает |
|---------|------------|
| `ahci_set_address_mapping(hhdm, phys, virt)` | Базы для перевода адресов DMA |
| `ahci_init(linux_name_base)` | Однократная инициализация всех AHCI-контроллеров |
| `ahci_device_count()`, `ahci_get_device_info(i, info)`, `ahci_select_device(i)` | Список и выбор дисков |
| `ahci_read_sector(lba, buf)`, `ahci_write_sector(lba, buf)` | Один сектор 512 байт |
| `ahci_flush()` | Команда `FLUSH CACHE EXT` (`0xEA`) |
| `ahci_device_name()` | Имя активного диска |
| `ahci_get_probe_stats(stats)` | Счётчики контроллеров, портов, SATA-дисков и ошибок IDENTIFY |

## Инициализация (`ahci_init`)

1. Из `storage_controller_list` берутся контроллеры типа AHCI. Лимит на накопители — 8 (`AHCI_DEVICE_LIMIT`).
2. Для контроллера включаются bus master и доступ к памяти, ABAR отображается через `mmio_map` (8 КБ).
3. Проверяется, что все DMA-адреса (списки команд, FIS, таблица команд, буферы) лежат в пределах 32 бит или что контроллер поддерживает 64-битную адресацию (`CAP.S64A`).
4. Включается режим AHCI (`GHC.AE`).
5. Для каждого порта из `PI`: если на порту есть SATA-диск (`SSTS.DET` = 3, `IPM` = активен, сигнатура `0x00000101`), выполняется IDENTIFY. Результат заполняет `struct ahci_device`: модель, серийный номер, число секторов, признак LBA48.
6. Имена дисков выдаются по `linux_name_base + device_count`.

## Выполнение команды (`issue_command`)

На каждую команду драйвер делает полный цикл:

1. Останавливает порт (`stop_port`, сброс `ST` и ожидание `CR`).
2. Очищает командный список, FIS и таблицу команд. Прописывает физические адреса в `CLB`, `FB`.
3. Заполняет заголовок команды (слот 0) и таблицу команд: FIS Host-to-Device, команда, LBA, счётчик секторов, один PRDT-элемент на 512 байт.
4. Запускает порт (`start_port`: `FRE` и `ST`), ждёт, пока `TFD` перестанет показывать `BSY` и `DRQ`.
5. Выставляет `CI` бит 0 и ждёт, пока бит сбросится. Ошибка `TFES` в `PORT_IS` прерывает ожидание и возвращает ошибку.

Команды чтения и записи: `READ DMA EXT` / `WRITE DMA EXT` (`0x25`, `0x35`) для LBA48, `READ DMA` / `WRITE DMA` (`0xC8`, `0xCA`) для LBA28.

## Где используется

- `src/drivers/storage/block_device.c` — блочный слой вызывает `ahci_*` для дисков, выбранных как AHCI-транспорт.
- `src/drivers/storage/storage_probe.c` — классификация контроллера.

## Ограничения

- Прерывания портов выключены (`PORT_IE = 0`), драйвер работает только опросом. Долгая команда блокирует вызывающий поток до таймаута `AHCI_TIMEOUT` = 10 000 000 итераций.
- Одна команда за раз, всегда в слоте 0. Очередь команд (NCQ) не используется.
- Каждая команда останавливает и заново запускает порт. Это медленно, но надёжно. Пропускная способность заметно ниже возможной.
- Один сектор за команду. Блочный слой не объединяет запросы на уровне AHCI.
- Поддерживаются только ATA-диски (сигнатура `0x00000101`). ATAPI-устройства (оптические приводы) и порт-мультипликаторы не поддерживаются.
- Горячее подключение SATA-портов не отслеживается: драйвер опрашивает диски только при инициализации.
- В проекте нет зафиксированных результатов проверки AHCI на конкретном железе или в QEMU. При проблеме начинайте с `ahci_get_probe_stats` и лога строк `ahci`.
